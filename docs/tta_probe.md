# TTA 探针：逻辑回归上做测试时自适应，有效吗？

> 起因：老师说 TTA（Test-Time Adaptation）方向好。这份记录回答一个问题——
> 把它接到我们这种十几维逻辑回归上，到底会不会涨。

## 一、为什么不能照搬经典 TTA

经典 TTA 的三条主路都要求深度网络：

| 做法 | 依赖 | 我们能不能用 |
|---|---|---|
| BN 统计量更新 | BatchNorm 层 | ✗ 逻辑回归没有 BN |
| TENT（熵最小化 + 只调 BN 参数） | 可求梯度的网络参数 | 部分能——但参数只有 13 个 |
| 伪标签自训练 | 足够容量去拟合伪标签 | ✗ 线性模型拟合不了自己的错 |

所以我们测的是**最朴素的那一种**：熵最小化 + 正例率锚定，直接对 (w, b) 走几步梯度。

## 二、方法（`tools/probe_tta.py`）

每个窗口，在**预测之前**取当窗无标签特征 X：

```
for step in range(steps):
    p  = sigmoid(Xs @ w + b)
    gz = p(1-p) · log((1-p)/p)          # 熵最小化梯度
    gz = gz + 2α(p̄ - ref_rate)·p(1-p)   # 锚定：防止坍缩成常数预测
    w -= lr · (Xsᵀ @ gz) / n
    b -= lr · mean(gz)
```

`ref_rate` = 初始训练集正例率（8%）。**全程不读 y**，所以这是合法的无监督自适应，不消耗标注配额。

## 三、结果（3 seed，21 窗，`results/tta/`）

| 组 | 平均窗 F1 | AP | 最差窗 F1 |
|---|---|---|---|
| frozen（不更新） | 0.6776 ± 0.0029 | 0.7801 | 0.0699 |
| tta（lr=0.01, 3 步，动权重） | 0.6783 ± 0.0029 | 0.7801 | 0.0699 |
| tta（lr=0.1, 10 步，动权重） | **0.6884** ± 0.0037 | 0.7799 | 0.0723 |
| tta（lr=0.1, 10 步，无锚定） | 0.6877 ± 0.0037 | 0.7799 | 0.0723 |
| **scaler_adapt（只换输入标准化统计量）** | **0.6468** ± 0.0014 | 0.7768 | 0.0563 |

三条路线都测了：**动权重**（熵最小化）、**只动阈值**（就是我们的 `calibrate`）、**动输入标准化统计量**（TTA 路线①的线性版）。
结果：动权重只换来 F1 假涨，换标准化统计量**明显更差**（−3.1pp F1），只有动阈值是真正有效的那个。

> 注：这里的 F1 是**平均窗**，与 `docs/experiments.md` 里的 overall F1（按样本量加权）不是一个口径，不能跨表比较。

## 四、三条解读

**0. 换输入标准化统计量是三种变体里最差的（−3.1pp F1）。**
这条路（TTA 路线①的线性版）原本被认为"既适应特征漂移、又不搞乱权重"，实测相反：
把标准化器换成当窗统计量，等于**用当窗数据把自己居中到均值 0**，而权重是在旧尺度上学的，
两者对不上；同时 500 条样本估计的均值方差本身噪声大。更糟的是，它把"特征整体平移"
这个真实的漂移信号，当成"需要消除的偏移"抹掉了——**而那正是 PSI 要检测的东西。**

**1. 加了力度能涨 1.08pp，但 AP 一动不动（0.7801 → 0.7799）。**
这正是我们此前的核心发现：**F1 涨不等于模型变强**。熵最小化只是把决策边界往"预测更自信"的方向推了一点，恰好让阈值更贴合当前窗的正例比例。特征的排序能力（AP）没有任何改善。

**2. 锚定项几乎没起作用。** 去掉 α 从 0.5 到 0，结果只差 0.0007——说明在这个参数量下熵最小化本身就不会坍缩，也说明它"能动的空间"本来就极小。

**3. 概念漂移是决策边界旋转，熵最小化推不到那个方向。**
它不知道"哪个方向才是新的正确方向"，只能让现有方向的判断更极端。这是无监督信号的固有上限：**没有标签，就无法判断朝哪转是对的。**

## 五、结论（分「能定的」和「不能定的」两栏）

**能定的：**

- **标准 TTA 在我们当前模型上做不了**，这是结构事实、与数据无关：TENT 与 BN 统计量更新都要求网络里有 BN 层，而 `NumpyLR` 是一层线性模型、13 个参数，没有可调的子空间。
- **在这条合成流上，"每窗对全部特征重算 z-score"这个具体操作有害**（0.6776 → 0.6468，AP 同步下降，3 seed 一致）。逐窗可查，`results/tta/`。
- **动权重（熵最小化）只换来 F1 的假涨**：+1.08pp，但 AP 从 0.7801 到 0.7799，一动不动。而我们已有的 `calibrate` 用更直接、更低成本的方式做同一件事。

**不能定的（重要）：**

- **不能说"TTA 无效"。** 我们只测了一种做法（全特征、每窗、无收缩）。没测的还有：只平移不缩放、新旧统计量收缩混合、只对漂移最强的几个特征做、把标准化作为重训的起点。这些一个都没跑。
- **我们其实没有一个能公平检验 TTA 的场景。** B 段的真实正例率从 8.2% 涨到 14.2%——它不是纯协变量漂移，而是"协变量 + 标签漂移"叠加。**用一个混了标签漂移的段去否定专门针对协变量漂移的方法，逻辑上不成立。**
- 而且严格的纯协变量漂移（P(Y|X) 完全不变、只有 P(X) 变）在合成时几乎造不出来——只要特征分布变，标签生成规则通常跟着变。这反而说明**真实世界里的"纯协变量漂移"可能同样罕见，绝大多数漂移是混的**。
- 由此指向一条更实用的结论：**不要按"漂移类型"选动作，要按"证据强度"选动作。** 这一条与 `policy.py` 的实际行为一致（level 2 时 covariate/concept/mixed 全走 retrain）。

**诚实的答辩口径：**

> 我们实现了无监督自适应（阈值校准），也测过梯度式 TTA。在这个模型类上，TTA 的标准实现没有落脚点（没有 BN 层），而我们能测的最朴素那一种只换来 F1 假涨、排序能力不变。我们**不宣称 TTA 无效**——只是还没拿到能公平检验它的数据：合成流造不出干净的协变量漂移，真实数据要等官方包。拿到之后第一步就测"标准化到底有没有帮助"，那是最便宜的一步。

## 六、必须说明的局限

本实验的 TTA 在**预测当窗之前**用当窗特征调整，属于 transductive（整窗可见）。
若官方评测要求**逐条流式输出**（拿到一条就要立刻给判断），这条路用不了。
本记录只回答"数学上能不能涨"，不回答"评测形态允许不允许"——后者要等平台接口明确。

## 七、误差累积（答辩时的加分点）

TTA 最著名的失败模式是**误差累积 / 确认偏误**：熵最小化会让模型对自己越来越自信，
最后塌缩成"不管输入是什么都输出同一个答案"（collapse to trivial solution），
而这个过程里模型自己感觉越来越有把握，没有任何信号告诉它错了。

我们这套系统本来就在防这件事，四道刹车里有三道已经跑在线上：

| 刹车 | 状态 | 在哪 |
|---|---|---|
| 锚点回滚（警报解除退回冻结基线） | 已有 | `main.py` 的 `edge` 分支 |
| 评估门（新版本不差于旧版本才留） | 已有 | `main.py` 的 `tolerance` 门 |
| 更新幅度限制 | 已有 | `calibrate` 单次 ±0.25 且 clip 到 [0.02,0.98] |
| 可靠样本筛选（只用高置信度样本） | 未做 | 理论上可加，但本实验里 AP 不动，加它收益存疑 |

**注意第三行**：我们说"只允许调阈值、不许动权重"，这不是一个待实现的设计，
而是 `calibrate` 已经做了两个多月的事。

答辩口径：

> 我们知道 TTA 会误差累积，所以没有直接上梯度式自适应；
> 我们实现的是它的**受限版本**——只动阈值、不动权重、幅度有上限、且必须过评估门。
> 我们实测过放开限制（直接对权重做熵最小化），结果是 F1 假涨、AP 不动。
