# 用原始数据模拟平台评分（A 包，2026-11-17）

> 结论先说：**A 包客观分里 `mean_gain` 约 8.26/15，`worst_stage` 约 0.08/5。**
> B 包我们不动模型 ⇒ `G=0`。C 包方向为正（RMSE −3.66%），但**算不出 G**，因为缺"参考上界"与阶段划分。
> 三个数都建立在"把 batch3–10 当成 8 个阶段"这个假设上，而平台真实的阶段划分没公开。

---

## 一、怎么算的

平台公式（评分表原文）：

```
G = (系统指标 − 静态基线指标) / (参考上界指标 − 静态基线指标)
mean_gain = 各阶段 G 的均值 × 15
```

三个量在我们的语境里对应：

| 量 | 我们的取法 | 来源 |
|---|---|---|
| 静态基线 | 官方 `checkpoint.npz`（v0）在 batch_k 上的 Macro-F1 | `out_ext/roll_all.json` 的 `frozen` |
| 系统 | 累积全部历史重训（`full` 臂）在 batch_k 上的 Macro-F1 | 同上，`arms.ce.full` |
| 参考上界 | **拿 batch_k 自己的标签重训 20 epoch**，在 batch_k 上的 Macro-F1 | 本脚本现算（`out_ext/sim_oracle.json`） |

脚本：`tools/exp_sim_score.py`（跑一次约 8 分钟，主要是 8 次 oracle 训练）。

**参考上界的口径要注意**：它用了该批的标签，等于"这道题考完再拿答案重学一遍"，只能当上界估计，**不能当成绩**。这也正是赛题组说的"每阶段全量标签重训"。

|---|---|---|---|---|

| b4 | 0.4893 | 0.6353 | 0.8333 | 0.4244 |
| b5 | 0.5225 | 0.8028 | 0.8277 | **0.9184** |
| b6 | 0.3228 | 0.5988 | 0.9913 | 0.4129 |
| b7 | 0.3267 | 0.7851 | 0.9990 | 0.6818 |
| b8 | 0.2664 | 0.7698 | 0.9535 | 0.7326 |
| b9 | 0.1852 | 0.7558 | 0.9931 | 0.7063 |
| b10 | 0.3806 | 0.6946 | 0.9931 | 0.5127 |

- `mean_G` = **0.5506** ⇒ `mean_gain` = **8.26 / 15**
- `worst_G` = **0.0156**（b3）⇒ `worst_stage` = **0.08 / 5**

## 三、读出来的三件事

**1. 第一轮几乎白干（b3，G=0.016）。**
第一轮手上只有 batch1 的 445 条，重训后只比冻结高 0.37pp，而这一批的上界是 0.83。**"最差阶段 5 分"基本被这一轮吃光**——但它是结构性的：任何人第一轮都只有 445 条。

**2. 越往后越好，但不是单调。**
b5 拿到 0.92（几乎追平上界），b6 掉回 0.41，b7–b9 稳定在 0.68–0.73，b10 掉到 0.51。掉的那两处对应"类别配比突变"（b6 甲苯突然占 20.3%、b10 又变回六类均匀）。

**3. 上界本身很"贵"。**
b7/b9/b10 的上界是 0.99——**用该批标签重训，几乎能满分**。这说明差距不在"模型不行"，在"没有该批标签"。

## 四、B 包与 C 包

**B 包：`G = 0`。**
我们六轮全部回退，提交的就是官方权重，系统 = 静态基线 ⇒ 分子恒为 0 ⇒ `mean_gain` 贡献 **0 / 15**。
这不是失误：B 包的六次尝试让 RMSE 全部变大（相对 681.1598：`+8.00 / +3.59 / +8.44 / +33.77 / +21.58 / +27.16`），继续训只会更差。

**C 包：方向为正，但算不出 G。**
- 我们的系统：RMSE **50.2190**（`sdk20`，首轮 `c_long` 900 轮并回滚到验证最好的第 997 轮），基线 **52.8686**，相对改善 **−5.01%**；同一镜像若只跑 300 轮（`sdk13`）为 50.4484（−4.58%）。
- 缺"参考上界"：C 包没有天然阶段划分（113089 条训练、23049 条验证，按发动机切），要造上界得自己定义阶段，等于自证。
- 粗估：若上界在 45–48 之间，G ≈ 0.2–0.4，折 **3–6 / 15**。

**三包平均（若平台按 1/3 各算）**：`(8.26 + 0 + 4.5) / 3 ≈ 4.3 / 15`。

## 五、还有三项没算（诚实说明）

| 项 | 分值 | 我们的估计 | 依据 |
|---|---|---|---|
| 最差阶段表现 | 5 | **0.08** | b3 的 G=0.016（已算） |
| 恢复速度 | 5 | 算不出 | 需要"漂移发生后恢复到漂移前 90% 所需阶段数"，A 包的阶段是换批不是漂移事件 |
| 稳定性/抗遗忘 | 5 | 约 2–3 | r8 在 batch2 上从 0.945 掉到 0.867（保持率 91.7%）；规则要求下降 ≤5% 才满分 |
| 资源效率 | 5 | 未知 | 按全体队伍排名分档，单独算不出；我们单轮 0.6–27 秒、Token 0 或 6–12/轮，属"很省" |

---

## 六、这套模拟的三个软肋（答辩要主动说）

1. **阶段是我们定的**（batch3–10 当 8 个阶段）。平台真实阶段划分未公开，若按"每 2–3 批一个阶段"，数字会变。
2. **上界是"作弊上界"**（用该批标签）。真实上界由组委会算，口径可能不同（比如他们允许全量重训 + 调参）。
3. **A 包的 train 只有 batch1**，所以我们的"系统"第一轮特别弱；若平台允许用"历史全部数据"（含之前批次），第一轮不会这么差。
