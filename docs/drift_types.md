# 漂移的四种类型，以及我们的代码对应到哪一类

> 这份记录回答两个问题：①我们的数据里到底有几种漂移；②我们的归因模块分不分得出来。
> 第二个问题的答案是**分不全**，这是一个真实的缺口，不是文档没写清。

## 一、四种类型（按"哪一层变了"分）

| 类型 | 变的是什么 | 不变的是什么 | 典型症状 |
|---|---|---|---|
| **协变量漂移** | 输入 P(X) | 规律 P(Y\|X) | PSI 高，AUC 不变，F1 因阈值错位而波动 |
| **概念漂移** | 规律 P(Y\|X) | 输入可能不变 | **AUC 下降**，F1 崩，PSI 可能毫无反应 |
| **标签漂移** | 结果比例 P(Y) | 规律 P(Y\|X) | **AUC 不变**，最优阈值移动，F1 随正例率漂 |
| **虚拟漂移** | P(X) 变了但模型判断不受影响 | — | PSI 高，AUC 和 F1 都不掉 |

## 二、我们的流里实际有几种（实测）

`data/synth_stream.csv` 各段正例率（实测）：

| 段 | 正例率 | 说明 |
|---|---|---|
| A_stable | 8.2% | 基准 |
| B_gradual | **14.2%** | 已经是标签漂移（比例从 8.2% 涨到 14.2%） |
| C_concept | **2.4%** | 比例爆跌 + 决策边界旋转，**三种漂移叠加** |
| D_recover | 7.2% | 回退 |

`data/g_gradual.csv` 更极端：第一段 24.6%，最后一段 **0.9%**。

**所以我们的合成数据不是"一种漂移"，而是三种叠加**。以前说"B 段是纯协变量漂移"是不准确的——它的正例率也从 8.2% 变到 14.2%。

## 三、关键实测：AUC 能把"标签漂移"和"概念漂移"分开

同一份冻结基线，逐段看 AUC 与 F1（`results/suite3/A_frozen/seed0`）：

| 段 | AUC | F1 |
|---|---|---|
| A_stable | 0.9993 | 0.8232 |
| B_gradual | **0.9996** | 0.8980 |
| C_concept | **0.7531** | 0.1615 |
| D_recover | 0.9998 | 0.8135 |

**B 段 F1 是四段里最高的，AUC 也没掉**——说明那段数据"模型其实判得对，只是阈值不合适"。而 C 段 AUC 掉到 0.75，是排序能力真的坏了。

对照 `D_edge_guard` 的 C 段：AUC 0.8668、F1 0.3442 —— 重训把排序能力拉回来了一部分。

⇒ **判断"该校准还是该重训"，看 AUC 掉不掉，比看 PSI 准得多。**
PSI 只知道"输入变了"，不知道"模型的排序能力有没有坏"。

## 四、我们的归因模块有什么缺口

`src/attribute.py` 当前的判据只有两个信号：`feature_psi_max` 和 `pred_psi`，输出四类：
`covariate` / `concept` / `mixed` / `none`。

**它没有一个叫"标签漂移"的类别，也没有用 AUC。** 后果：

- 一个"只有正例率变了、规律没变"的窗，会被判成 `concept` 或 `mixed` → 触发重训 → 白花算力，还可能把模型带偏到新比例上；
- 正确动作应该是**只调阈值**，代价几乎为零。

这不是理论问题：B 段的正例率就是从 8.2% 涨到 14.2%，我们的 `policy` 靠 `level==2 且 covariate → calibrate` 这条规则碰巧做对了，但理由是"输入变了"，不是"比例变了"——**判据和理由对不上**。

## 五、改进方案（未实施，需 Planner 裁定）

有延迟标签的前提下，每窗末可以算出 AUC，于是判据可以变成：

```
if AUC_drop > 0.05:            → concept   （排序坏了，必须重训）
elif |pos_rate - ref| > 0.3:   → label     （排序没坏，只是比例变了 → 只校准）
elif feat_psi > 阈值:          → covariate （输入变了，规律没动 → 校准）
else:                          → none
```

代价与风险：

- 需要把"最近一窗的标签"传进 `attribute()`，接口要改；
- **会改变所有已跑出来的结果**（`results/suite3` 全部作废，需重跑 24 次 × 3 seed）；
- 可能让 C 段被判成 `label`（如果 AUC 下降幅度不够大），从而只校准不重训 → C 段崩。

最后一条是真实风险：C 段 AUC 0.7531，相对 0.999 掉 0.246，远超 0.05 阈值，所以会正确判成 concept。但官方数据上未必这么干净。

## 六、结论

- 四种漂移里，**我们真正处理得对的是协变量和概念**；标签漂移目前是"碰巧做对、理由不对"；虚拟漂移靠"不动"这个默认动作兜住。
- **AUC 是比 PSI 更准的归因信号**，但我们没用它——这是下一步最值得改的地方，前提是官方数据到手、能验证不会让 C 段退化。
- 答辩时不要声称"我们能区分四种漂移"。准确的说法是：**我们用两条信号（输入分布 + 输出分布）判了四类归因，其中标签漂移与概念漂移的区分依赖延迟标签，目前尚未接入。**
