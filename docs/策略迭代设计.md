# 策略迭代：从"选动作"到"改策略"

> 状态：**设计稿**，未实现。落点 `src/contest_loop.py`（执行者写），本文只定义接口与记录格式。
> 目的：把 `train(rnd)` 从"拿证据选一个动作"改成"读历史 → 改策略 → 选动作 → 记结果"，
> 让评分表里"更新策略随经验积累而改进"这一条有东西可指。

---

## 0. 一句话

现在的 `train(rnd)` 是**无记忆的**：每一轮都从零开始看当前证据，输出一个动作。
改成**有记忆的**：先读过去每轮"试了什么、结果如何"，据此决定这一轮**该不该还试这个方向**。

LLM 的角色随之改变：从"四选一的分类器"变成"在**已被经验筛过的候选集**里拍板"的那一层。
规则的活是**决定"哪些方向还值得试"**（判死、平台期、失败模式），模型的活是**在这几个候选里挑一个并说明理由**——它挑的那个就是本轮执行的动作（`src/contest_loop.py:294` 的 `ask_model` 直接返回 `action`，`:310` 用它分支）。所以"换成人写的规则结果不会变"这句话**不成立**：规则只缩候选集，最终一票在模型手里；它给的理由也逐轮写进 `hypothesis`，可追溯。
**模型不碰的是超参**——`learning_rate`、`epochs` 由策略层固定，模型只选动作名。

## 1. `rnd.history()` 到底返回什么（源码确认 + 不确定的部分）

### 确定的部分

`contest_harness/round.py:151-163`：

```python
def history(self):
    records = self._rpc("history_request", "history_response")["records"]
    if not isinstance(records, list):
        raise HarnessError("HISTORY_INVALID")
    identifiers = []
    for record in records:
        if not isinstance(record, dict) or not isinstance(record.get("id"), str) or not record["id"]:
            raise HarnessError("HISTORY_INVALID")
        identifiers.append(record["id"])
    if len(identifiers) != len(set(identifiers)):
        raise HarnessError("HISTORY_INVALID")
    self.history_ids = identifiers
    return records
```

⇒ SDK **只保证**：`records` 是 `list[dict]`，每条有唯一非空字符串 `id`。**其余字段一概不校验、不保证**。

### 不确定的部分（必须承认）

- 平台到底往 `records` 里塞哪些字段，**本地无法验证**（假宿主是我们自己写的，验不了平台行为）。
- 官方包里的 `history.jsonl` **不是这个东西**——那是训练日志（每 epoch 一条 `stage_id`/`epoch`/`loss`/`validation`），不是轮次决策历史。别拿它当依据。

### 因此的设计约束

**不能依赖平台给的额外字段。** 经验只能来自：

1. 我们自己上一轮 `finish(...)` 写进去的东西（`hypothesis` / `change_summary` / `reason` / `configuration`）；
2. 我们自己 `rnd.save_state()` 存到 `/state` 的东西；
3. 兜底：什么都没有时，用冷启动默认策略。

## 2. 三层经验来源与降级

| 层 | 来源 | 可靠性 | 用途 |
|---|---|---|---|
| L1 | `rnd.history()` 里上轮 `configuration["policy_state"]` | 中 | 主路径 |
| L2 | `rnd.save_state()` → `/state/policy_state.json` | 高（若平台保留 `/state`） | 备份 |
| L3 | 无历史 | — | 冷启动：按固定顺序试 `lr_lo → calib → continue10` |

`load_state(rnd)` 按 L1 → L2 → L3 依次尝试，任何异常都降级，**不抛**。

## 3. 经验表结构

```json
{
  "version": "meta-v1",
  "noise_se": 0.0127,
  "rounds": [
    {"round": 1, "action": "lr_lo",  "parent": 0.7140, "score": 0.7210, "delta":  0.0070, "accepted": true},
    {"round": 2, "action": "lr_hi",  "parent": 0.7140, "score": 0.6802, "delta": -0.0338, "accepted": false}
  ],
  "directions": {
    "lr_lo":  {"tries": 1, "accepts": 1, "rejects": 0, "best_delta":  0.0070, "status": "open"},
    "lr_hi":  {"tries": 2, "accepts": 0, "rejects": 2, "best_delta": -0.0338, "status": "dead"},
    "calib":  {"tries": 0, "accepts": 0, "rejects": 0, "best_delta":  0.0000, "status": "open"}
  },
  "plateau": {"since_round": 3, "best_score": 0.7210, "streak_below_noise": 2},
  "last_action": {"round": 2, "action": "lr_hi", "delta": -0.0338}
}
```

字段约定：

- `directions[key].status ∈ {"open", "dead", "exhausted"}`；`dead` = 被元规则判死，`exhausted` = 试满次数但不好不坏
- `delta` = `score − parent.score`，正负与原值同单位（分类用 macro-F1，回归用 **−RMSE**，保证"越大越好"统一）
- `noise_se` 每轮从历史 delta 估计；历史不足 3 条时用固定先验 `0.0127`（A 包 bootstrap SE）

## 4. 三条元规则（人写的先验，agent 只执行）

| 编号 | 规则 | 触发条件 | 效果 |
|---|---|---|---|
| **R1 方向判死** | 同一方向连续 2 次 `delta < −noise_se` | 见 `directions[*].rejects` | 该方向 `status=dead`，永久不再入选 |
| **R2 平台期** | 连续 3 轮 `|delta| < noise_se` | `plateau.streak_below_noise ≥ 3` | 停止探索，只允许 `calib`（可逆、低成本） |
| **R3 失败模式** | 上一轮 `action == "retrain"` 且 `delta < −noise_se` | `last_action` | 本轮优先 `calib`，不重训 |

三条都是**从经验表算出来的**，不需要额外信息。

**边界声明（必须写进文档和答辩）**：这三条元规则是人设定的先验，不是 agent 自己发明的。
准确说法是"**给了它三条元规则和一份经验表，它的后续行为随经验改变**"，
不是"**agent 自己学会了什么时候停**"。

## 5. 决策流程（伪代码，落点 `src/contest_loop.py`）

```python
def run_round(rnd):
    st   = load_state(rnd)                 # L1 → L2 → L3
    hist = read_history(rnd)               # 容错：字段缺失也不崩
    st   = merge(st, hist)                 # 从 history 补账

    plan = rank_directions(st, rnd.dataset_key)   # 排除 dead，按 期望收益/成本 排序
    if not plan:                                  # 全判死 → 守成
        plan = ["calib"]

    action = plan[0]
    reason = explain(st, action, plan)      # 见第 6 节

    # LLM 的唯一作用：在 plan[:3] 里挑一个 + 给理由（白名单，不给超参）
    if llm_available(rnd):
        try:
            choice, why = ask_llm(rnd, st, plan[:3], reason)
            if choice in plan[:3]:
                action, reason = choice, why
        except Exception:
            pass                            # LLM 缺席，用规则结果继续

    result = run_action(rnd, action)        # 训练/校准，返回 score
    delta  = result.score - st.best_score
    accepted = delta > 0

    st = update_state(st, rnd.round_index, action, result, delta, accepted)
    return finish(rnd, st, action, reason, delta, accepted)
```

关键点：

- **LLM 挂了不影响流程**（`except` 兜住，用规则结果）；
- **LLM 只能在 `plan[:3]` 里挑**，不能自己造动作，更不能给超参；
- **但它挑中的那个就是最终执行的动作**（`choice in plan[:3]` 才覆盖 `action`）——规则决定"能选哪些"，模型决定"选哪个"；
- `run_action` 返回的 `score` 必须与 `parent` 同口径比较。

## 6. `hypothesis` 怎么写（三个真实例子）

要求：**可追溯到数字**，不写空话。

1. 方向判死
   > 前两轮 `lr_hi` 分别回退 −3.38pp 与 −3.49pp，均超过噪声带 1.27pp，按 R1 永久排除该方向；本轮改试 `continue10`。

2. 平台期
   > 连续 3 轮改进量 0.12pp / 0.08pp / 0.05pp 均小于噪声带 1.27pp（R2），判定已到平台期，停止探索，本轮只做阈值校准（可逆，代价 <1s）。

3. 失败模式
   > 上一轮 `bs256` 重训后回退 −4.11pp（R3），本轮不再重训，先做校准；若校准仍无效，下一轮转入守成。

反面教材（别写）：「本轮尝试优化模型性能」「根据分析决定重训」——没有数字、没有引用历史，评委会认为在编。

## 7. 记录格式（每轮一行 JSONL）

```json
{"round": 5, "parent_sha": "e3c9bf73...", "strategy_version": "meta-v1",
 "plan": ["lr_lo", "calib", "continue10"], "action": "calib", "action_source": "rule",
 "reason": "R2 平台期：连续 3 轮 < 噪声带，停止探索",
 "before": {"macro_f1": 0.7210}, "after": {"macro_f1": 0.7194},
 "delta": -0.0016, "accepted": false,
 "attempt_ordinal": 1, "rounds_since_accept": 2,
 "state_after": {"best_score": 0.7210, "dead_directions": ["lr_hi", "bs256"]}}
```

字段说明：

- `plan`：本轮候选排序（可追溯"为什么选它"）
- `action_source ∈ {"rule", "llm", "llm_fallback", "cold_start"}`
- `attempt_ordinal`：本轮第几次尝试（一动作一轮时为 1）
- `rounds_since_accept`：距上次被接受的轮数——**这是"效率"的唯一诚实指标**

## 8. 关于"效率提升"的诚实口径

**不要声称"后期找到答案更快"**——我们的数据是反的：A 包 10 轮里接受在第 1、3 轮，之后 7 连拒。

能诚实记录的只有：

- `rounds_since_accept` 的变化（是否更早收手）
- `dead_directions` 的数量（排除掉多少个方向）
- 停止时消耗的轮次（对比"穷举到动作空间耗尽"）

如果要写"效率提升"，只能写成：
> 固定动作表在第 9 轮因"动作空间耗尽"被动停止；加入 R1/R2 后，第 4 轮即判定平台期，第 5 轮起不再探索——**少消耗 4 轮**。

这是"省轮次"，不是"每次更快"。轮次是 `workspace_suite.rounds` 的有限资源，省下来是真的。

## 8.1 如何验证（不需要消耗 trial）

**`delta` 不依赖平台给分，`train_run` 自己测。** 这是 `baselines/train.py` 里的两行：

```python
validation_before = metrics(model, validation)   # :89，加载父模型后立刻测
...
"validation_after": records[-1]["validation"]    # :115，训完最后一轮测
```

两者都在同一次 `train_run` 里现算，`exp` 里的历史分数**一个都没参与**。所以只要训练没抛异常，`delta` 一定是个数。

本地复现（不需要平台、不需要假宿主）：

```python
from baselines.train import train_run
report = train_run("A", train_path, val_path, out, resume="checkpoint.npz", epochs=3)
report["validation_before"], report["validation_after"]
```

实测（A 包、从官方 ckpt 续训 3 epoch、0.05 秒）：

```
validation_before: {"accuracy": 0.8786, "macro_f1": 0.71403}
validation_after : {"accuracy": 0.8859, "macro_f1": 0.71874}
delta = +0.0047   ← 噪声带 0.0127，属于带内
```

⇒ **拿一次 trial 去验"能不能拿到分数"是浪费**（trial 扣次数且失败不返还）。trial 要留给最后一次全链路。

`delta` 为 `None` 只有三种情况，都不是"第一轮没有历史"：

| 情况 | 结果 | 处置 |
|---|---|---|
| `action == "noop"` | 不训练，`metrics={}` | 合理，本来就没动 |
| 训练抛异常 | 回退父模型 | **记 `failed` 标志**，下一轮 R3 不走校准而走 `noop` |
| report 缺字段 | `None` | 不该发生，发生了要查 |

**每轮的可观测字段**（写进 `change_summary`，不依赖平台回传）：

```
parent_found=True；trained=True；before=0.7140；after=0.7187
```

真机上如果 `parent_found=False`，说明 `/previous` 没读到、退回了内置权重——**这一条比任何分数都重要**，因为退权重等于每轮都在原地打转。

## 9. 边界（写进作品文档 + 答辩）

- 元规则是人写的；agent 做的是"在元规则下积累经验并改变后续行为"；
- 经验表只覆盖"试过哪些方向、结果如何"，不覆盖"为什么这个超参有效"；
- 冷启动（第 1 轮无历史）走固定顺序，不算"策略迭代"；
- LLM 可能缺席（超时/抖动），缺席时行为退回纯规则，**不声称 LLM 一定参与**；
- **动作空间的宽度由平台约束决定，不由我们的策略决定。** 官方续训接口只允许调整 `epochs` / `learning_rate` / `batch_size`，且强制保留父检查点的随机种子与网络宽度（`train.py:73-78`：`resume must preserve the checkpoint's random seed`、`resume hidden width must match checkpoint`）。因此在单一父模型下，同一动作的重复执行是确定性的、结果逐位相同。我们的策略层不试图在等价动作间制造虚假差异，而是把"识别等价性并停止"作为主要收益来源。

**这条的实测证据**（本地三轮，假宿主 + 内置父权重，两个包并列）：

```
A  retrain_10  轮2 = 轮3 = -0.008391168058790033
C  retrain_20  轮1 = 轮3 = -0.062851972913478
```

两行、两个包、两个动作，delta 都逐位相同 ⇒ **"同一父模型 + 固定 seed ⇒ 重复动作在数学上等价"是结构性事实**，不是某个包的偶然。若无元规则，这类**等价的重试**会一直消耗轮次直到预算耗尽。**动作空间越窄，"学会停"越值钱**——这是 R1/R2 存在的理由，不是缺陷的掩饰。

### 9.1 被移除的动作：`calibrate`

动作集最初是 `("noop", "retrain_20", "retrain_10", "calibrate")`。`calibrate`（阈值校准）**移植自原型系统的二分类场景**。

三个官方包的输出空间：

| 包 | 输出 | 有阈值可调吗 |
|---|---|---|
| A | 六分类 `[{"label","score"}] × 6`，取最高分 | ❌ 只有 `argmax` |
| B | 回归 `{"value": float}` | ❌ |
| C | 回归 `{"value": float}` | ❌ |

⇒ **该动作在任何一包上都没有对应的执行语义**。它不是"没实现好"，是**从移植过来那天起就不成立**。

直接证据：`src/contest_loop.py` 里它一度落到训练分支、跑成了 `retrain_20`，`best_delta` 与前一轮**逐位相同**（C 包 `-0.062851972913478`）——一个动作只有在被真正执行时才会产生自己的数，它没有。

已从动作集移除，R3 改为 `noop`（保留父模型、观察一轮）。

> **从别的任务搬来的动作，要先证明它在新任务的输出空间里有定义。**
