## 三十秒看懂

**这道题问的不是"怎么把模型训得更准"，而是"数据变了，你该不该动手"。**

赛题给三个已经训好的小模型（六类气体分类、轴承寿命、发动机寿命）和一份新批次数据。新批次和训练批次的分布差得很远（A 包 128 个特征里 118 个的 PSI 超过 0.25），直接拿旧模型去用会掉分，但盲目重训会掉得更多。

我们的系统分两层，边界是赛题规则划的：

| 层 | 做什么 | 为什么在这一层 |
|---|---|---|
| **推理层**（提交的镜像） | 纯前向：逐行读、逐行写，不学习、不调参 | `baselines/predict.py:1` 写着 "no model execution hooks"，测试会拒绝任何带标签字段的输入 |
| **轮层**（真正的自进化） | 每轮：诊断 → 决定改什么 → 训练 → 验证集判一次 → 变好采纳、变差回退 → 记账 | 规则允许"用验证集挑超参"，禁止"用验证集算统计量"——两者的界线是**是否产生新参数** |

十轮走完，交出一个 checkpoint；镜像只负责拿它做纯预测。

| A | 六类气体分类（Macro-F1 ↑） | 0.7140 | **0.7210** | +0.70pp（+0.98%，**在噪声带内**） |

**但校赛只发了一批数据，所以真正的十轮形态我们自己造了一组**：只用已经到手的批次训练、在下一批没见过的数据上测（第 1 轮 [1]→测 b3，第 2 轮 [1,3]→测 b4，……，第 8 轮 [1..9]→测 b10）。八轮均值：冻结模型 **0.386** → 累积续训 **0.705（+31.9pp）**，而且没有遗忘（第 1 轮 445 条得 0.598，第 8 轮 9066 条得 0.695）。**这一组才是企业赛要考的能力**，详见附录 B。

**一句话结论**：**"该不该动"这件事的答案，取决于有没有新数据。** 校赛只有 batch1、没有新批次，这时"判断不该动"比"更聪明地动"更值钱——A 包 10 轮里 8 次回退、B 包 6 次尝试全负、C 包 10 轮里 4 次回退。但在企业赛形态里（每轮都有带标签的新批次），我们对同一个评估门做了证伪：**加上门反而把八轮均值从 0.705 拖到 0.574**，因为"在旧批次上变好"和"在新批次上变好"根本不同步。所以我们的结论不是"永远别动"，而是"**没有可靠信号时靠纪律，有可靠信号时靠数据**"。

这个结论有边界（见第四节末：同分布（同批次）训练时 focal 能把 A 包从 0.6880 拉到 0.8871，但跨批次时同样的替换反而降到 0.7133）。

> **另一件要先说清楚的事：我们的"漂移对抗方法"本身不会进化。**
>
> 分三层看：**方法层**（重训 10/20 epoch、不动作、调学习率）是赛前用实验定死的，运行期不新增、不改进；**动作空间**（`noop` / `retrain_20` / `retrain_10` / `retrain_300`）是写死的四个；**选择策略**会变——哪个方向被判死、是否进平台期、上轮是否失败，这些随轮次更新，但只是在三个固定选项之间换着选。
>
> 也就是说：**方法在赛前进化，模型在赛中进化，选择策略在赛中缓慢变化，唯独"有哪些方法可用"不变。**
>
> 我们不把这条当减分项藏起来，因为它是可核查的：`src/contest_loop.py` 里 `ACTIONS` 是常量，`R1/R2/R3` 三条元规则是我们手写的先验，代码里没有任何"生成新动作"的路径。**一个声称自己能发明新方法的系统，在 1689 条样本、±1.3pp 噪声带的条件下，多半是在拟合噪声**——这正是我们一路否掉的评估门、集成、TTA 的失败方式。

## 零、关于提交表单里 `model` / `model_source` 两个字段

**`model` 与 `model_source` 已按平台下拉可选项填为 `Qwen/Qwen3.8-27B` + `base`**：平台只提供 `Qwen/Qwen3.5-4B` 与 `Qwen/Qwen3.8-27B` 两个模型（`/models` 实测一致），表单没有"不使用大模型"选项；`base` 表示直接使用平台提供的原版权重、未做任何微调，与事实相符。我们**没有**用大模型做任何预测，Qwen 只出现在训练期"按协议每轮调用一次模型"这一步，见下文。

- **训练期按平台协议每轮调用一次模型**：新版 Harness SDK（`contest.harness.workspace.v2`）在 `train(rnd)` 里有硬检查——本轮没有任何模型调用就抛 `MODEL_CALL_REQUIRED`，整轮训练不成立。所以每轮至少一次真实调用是**协议要求**，不是我们的选择。调用由平台 host gateway 代持密钥，镜像里不存任何 API Key，也没有 Qwen 权重。
- **模型参与动作选择，但选择范围被策略层限定**：候选动作由规则给出（A：`noop` / `retrain_20` / `retrain_10` / `retrain_300`；B：`b_ladder` 十档阶梯；C：`c_long` 900 轮 / `noop`），已排除被 R1 判死的方向与平台期内不再有效的方向；模型只在候选内选一个并写理由。
- **模型不产出训练超参**：`learning_rate`、`epochs` 等由策略层固定，不让模型生成。
- **推理期零调用**：提交镜像里的 `predict` 是纯 NumPy 前向（`harness/net.py` 那套 `clip((x−mean)/scale) → tanh → linear`），不发任何网络请求，不读标签，不拟合任何统计量。

`model_source = base` 的语义是"直接使用平台提供的原版权重、未做任何微调"，平台侧会弹二次确认要求"训练记录必须如实说明未使用微调权重"。这是三个选项（`base` / `sampler` / `legacy`）里唯一符合事实的一个——我们没有在 PyTRiO 上训练过任何 Qwen 权重。

**请以本文件所述为准**：

- 镜像是 `python:3.11-slim` + numpy + 三个 NumPy 前向文件 + 六个 1 万～4 千参数的 `.npz`，解压即可核对；
- 训练记录（SwanLab）里全部是逻辑回归 / 小型 MLP 的实验，没有任何 Qwen 或大模型的训练；
- 三个包的分数（A 0.7210 / B 452.13 / C 50.07）全部由这些小模型产出，与 Qwen 无关——Qwen 只出现在训练期"选哪个动作"这一环，不参与任何一次预测打分。

## 一、我们理解的问题

赛题给的是三个已经训练好的小模型和一份数据包，问的是：**当数据分布变了，这套东西还能不能用、该不该动、动了会不会更糟。**

三个包的结构决定了问题的形状：

| 包 | 任务 | 指标 | 官方基线 | 训练集 / 验证集 |
|---|---|---|---|---|
| A | 六类气体识别 | Macro-F1 ↑ | 0.7140 | batch1（445 条） / batch2（1244 条） |
| B | 轴承剩余寿命 | RMSE ↓（分钟） | 681.16 | 7032 / 1679 |
| C | 发动机剩余寿命 | RMSE ↓（循环） | 52.87 | 113089 / 23049 |

关键事实有两条，都是从官方包里直接读出来的：

1. **A 包训练集全来自 batch1、验证集全来自 batch2**，是两个不同月份的测量，不是随机切分。所以这不是"同分布上的调参题"，是**跨批次迁移题**。
2. 官方 `baselines/predict.py` 第 1 行写着 `no model execution hooks`，`tests/test_baselines.py:65-72` 规定输入里出现 `RUL`/`true_rul` 之类字段就直接抛错，`TRAINING_GUIDE.md:32` 禁止验证集参与拟合**任何**统计量。

第 2 条把可行空间压得很窄：**推理期不能自适应，任何"运行时改模型"的方案在合规层面就不成立**。所以"自进化"只能发生在**训练轮**这一层——每一轮是一次完整的闭环：诊断 → 决定改什么 → 训练 → 验证 → 记账 → 接受或回退。

这个判断改变了整个系统的形态。我们没有去做一个"运行时自动调整"的引擎，而是做了一个**把实验本身管起来的引擎**，它交付的是一个可以逐轮复看的决策链。

### A 包的真问题：类内漂移比分出两个类所需的距离还大

A 包数据按类别成块排列，所以"按 100 条切窗算 PSI"这种常规做法在这里是无效的（切出来的是"乙醇块 vs 丙酮块"，那是类间差异，不是漂移）。我们改成**同类跨批比较**：拿 batch1 的某一类，和 batch2 的同一类比，按该类每维自己的标准差标准化，看中心移了多少个 σ。

| 类别 | 类内跨批位移（中位） | 与其他类的距离（batch1 内，中位） |
|---|---|---|
| Acetaldehyde | **0.96σ** | vs Ethanol 仅 **0.17σ** |
| Toluene | 0.77σ | vs Ethanol 1.38σ |
| Acetone | 0.64σ | vs Ethanol 0.42σ |
| Ethanol / Ethylene / Ammonia | 0.50σ / 0.50σ / 0.47σ | — |

**同一种气体换一个批次，位置就移动 0.47–0.96σ；而"乙醇"和"乙醛"这两个类别的中心只隔 0.17σ。**

也就是说：模型是靠"这两团只差 0.17σ"来区分乙醇和乙醛的，而乙醛自己一换批次就移动了 0.96σ——**是它和乙醇间距的 5.6 倍**。移动之后它整个落进乙醇的范围里，这就是召回 0.00 的直接机制，比"类别不平衡"这个说法精确得多。

**但换成欧氏距离，"谁在动"就反过来了。** 同一套标准化下：

| 量 | batch1 | batch2 |
|---|---|---|
| 乙醇中心跨批位移 | — | **93.94** |
| 乙醛中心跨批位移 | — | **9.90** |
| 两类中心距 | 6.19 | 94.49 |

主因不是"乙醛搬家了"，而是**乙醇这一团在 batch2 里变宽、移位，把乙醛整个罩住**（batch2 的乙醇从 90 条涨到 164 条，覆盖的浓度范围扩了）。

两个口径说的是不同的事，必须一起看：逐维中位数说"典型维度几乎没动"（0.1–0.3σ），欧氏距离说"有个别维度塌了极多"（个别传感器几十个 σ）。**更准确的说法是：不是乙醛变了，是乙醛的邻居扩张到了它头上。** 这一条对我们更不利——因为"补数据"能补乙醛，但补不了"乙醇的分布随批次变宽"。

这也解释了另外两件事：为什么只有重训有效（重训重新标定每一团的中心；校准只动阈值、标准化只统一尺度，都跟不上"位置和形状同时变"）；为什么归因在真数据上退化成单一结论（当类内移动和类间间距同量级时，任何"按分布判断是哪类漂移"的方法看到的现象都是"所有东西都在动"）。

数据与复现：`results/a_within_vs_between.json`（逐维中位数）与本节的欧氏距离计算。

### 还有第三个尺度：块内也在漂

把每一个"批次 × 类别"的块，按采集顺序切成前后两半，比较这两半的中心位移（同一套标准化）。45 个块的中位位移是 **0.51σ**：

| | 位移（中位） | 例子 |
|---|---|---|
| 块内（同批同类，前半 vs 后半） | **0.51σ** | 最稳 batch10 丙酮 0.08σ；最烈 batch8 丙酮 **28.2σ**、batch5 乙烯 13.9σ |
| 块间（同类，跨批次） | 0.47–0.96σ | 见上表 |
| 类间（同批，不同气体） | 0.17–1.38σ | 乙醇 vs 丙酮 0.42σ |

**同一瓶气体先测的和后测的，差别（0.51σ）与两种不同气体之间的差别（0.42σ）相当，个别块甚至大两个数量级。** 机理是传感器基线随测量时长自己爬升——batch10、batch7 那种"短时间测完 600 条"的块内部很干净（0.08–0.13σ），拖得久的块内部就漂。

这一条直接判定了我们早期做法的死刑：**在 A 包上"按 100 条切窗算 PSI"从一开始就没有意义**——一个窗口同时跨了类别边界和块内漂移两个陷阱，算出来的东西测的是"这 100 条里恰好有哪几种气体"，不是漂移。这也是我们后来拒绝在 A 包上做窗级归因验证的原因（见 §六 第 6 条）。

数据与复现：`results/a_within_vs_between.json`、`results/a_intra_block.json`。

## 二、系统做了什么

五个环节，每一环都对应评分表上的一项：

```
诊断（这轮的偏差是什么性质）
  → 决策（该动哪一项，还是不该动）
  → 执行（只动允许动的那几个旋钮）
  → 验证（在新数据上真的更好了吗）
  → 记账（花了多少、赚了多少、为什么这么决定）
```

**诊断**用的是三条互相独立的信号：输入分布 PSI、输出分布 PSI（一律用冻结基线的打分算，避免模型自己被带偏后污染监测）、以及延迟到达的 AUC。前两条无标签、可实时；第三条要等标签，但它是唯一能分辨"排序坏了"和"阈值偏了"的信号。

**决策**是一个带元规则的策略层，不是固定规则表，也不是从零学出来的策略。它由三部分组成：动作白名单（`noop` / `retrain_20` / `retrain_10` / `retrain_300`，宽度由官方接口的硬约束决定）、三条元规则（方向判死 / 平台期 / 失败模式，人写的先验，决定"什么时候不该再试"）、经验表（逐轮记录每个方向的尝试、接受、拒绝与最好结果，存 `/state` 跨轮累积）。三者的分工是刻意的：**元规则定"怎么判断"，经验表记"判断过什么"，模型调用于在合法动作里选一个并给出理由。** 不在元规则之外让模型发明新规则——只有一条数据流的情况下，无法验证一个自己发明规则的系统。

**执行**的动作空间被官方硬约束收窄到三个：`epochs` / `learning_rate` / `batch_size`。`baselines/train.py:74` 会拒绝改变随机种子的续训，等于把"换模型结构"这条路封死了。

**验证**在两个场景下含义不同，必须分开说。**有标签的静态数据上**（校赛）：新一轮的指标必须在验证集上更好才接受，否则回退——这条拦住了我们十轮链里 8 个方向。**看不到下一批的滚动场景里**（企业赛）：评估门被我们自己的实验证伪了（滚动留一批上带门 0.5743、不带门 0.7050，**−13.1pp**），因为"新模型在旧批次上先升后降、在新批次上单调升"，用旧批次判断等于系统性拒绝正确的动作。所以企业赛不设评估门，改由元规则 R1/R2 决定何时停手。

**记账**写进 `training.json` 的父子链条和 SwanLab，每一轮的假设、动作、指标、耗时都可查。

### 一个必须说清的分工：推理零状态，训练期才跑五环

打开镜像，`predict` 路径上只有 `predict.py` / `router.py` / `net.py`——**读一行、路由、算、吐一行，不保留状态、不改模型**。依据是 `TRAINING_GUIDE.md:32`：验证集和隐藏测试集不得参与拟合任何统计量。所以推理期必须是零状态、零拟合的纯前向。

五环跑在 **`train(rnd)`** 里。新版 SDK（`contest.harness.workspace.v2`）把训练轮交给选手代码：`train` 可以读本轮数据、读历史、调一次模型、提交候选、写状态。诊断、决策、执行、验证、记账都在这里发生，结论落进 `configuration` / `hypothesis` / `change_summary`，平台原样留痕。

两者不冲突：**推理期什么都不能改，训练期什么都可以改**——这正是"每轮在下发数据上迭代"的协议设计。

两个阶段的评测入口不同，所以比的东西也不同：

- **校赛**：评测方式是"喂输入、收输出"，只跑 `predict`。这一阶段比的是**镜像的工程质量**（正确、健壮、离线、跨发行版）和**文档/记录的质量**（迭代线证据、否定结论、口径论证）。
- **企业赛**：带工作区、每轮下发新批次数据，`train(rnd)` 与 `predict` 都跑，五环在训练轮里真实运行，每一轮的假设/动作/指标/理由由平台留痕。

我们不把这两件事混着说，因为混着说在答辩时一问就露：**校赛阶段"自进化"的证据是记录，企业赛阶段才是运行时行为。** 两个阶段共用的同一份代码、同一个镜像。

## 三、三个包上的结果

**逐轮迭代**，全部跑完，全量验证集：

| 包 | 官方基线 | 我们最好的 | 变化 | 接受 / 被拒 |
|---|---|---|---|---|
| A 六类气体（Macro-F1） | 0.7140 | **0.7210** | **+0.7pp（+0.98%），在噪声带内** | 2 / 8（10 轮） |
| B 轴承 RUL（RMSE ↓） | 681.1598 | **452.1295** | −33.6%（十档阶梯，采纳 3 档） | 3 / 10 |
| C 发动机 RUL（RMSE ↓） | 52.8686 | **50.0744** | **−5.29%** | 1 / 9（首轮一次训 900 轮并回滚最好一轮，其余 noop） |

**这些轮次是怎么跑的，必须先说清，否则会被高估。**

赛题要的是"基于父检查点的多轮迭代"，不是"一条不许分叉的直线"。我们的做法是：**每轮从当前最优检查点出发训练，在验证集上评估；不如当前最优就退回父节点，换一个方向重开。** 被拒绝的分支不删除，`training.json` 里逐轮可查 `parent_checkpoint_sha256`。

三条线加起来 **26 轮**，结构各不相同（`records/` 共 26 份记录）：

- **A 包 10 轮，树形**：r01 → r03 是主干。挂在 r03 下面的七个分叉（r04–r08 五个超参分叉，加 r09 `lr=0.002`、r10 `epochs=40`），**没有一个超过它的 0.7210**；更早的 r02 挂在 r01 下，同样被拒。**十轮里八个方向被拒绝，这不是“没做出东西”，是“系统有能力拒绝变差的方向”八次的直接证据。**

  补这两轮是因为前八个动作（学习率三档、batch 两档、续训轮数两档）已经穷尽，不是凑数——第 9 轮时程序输出 `动作空间耗尽` 并主动停止。

  顺带一条：补轮次**不需要重打镜像**——两个分叉没有改动主干，`out_chain_a/r03/checkpoint.npz` 的 SHA256 与 `harness/checkpoints_trained/A.npz` 逐位一致（`E3C9BF73…9C8C`），所以 `dist/zhixun-harness-1.3.tar` 及其 sha256 照旧有效。
- **B 包 6 轮，六次平行**：每次都从官方权重出发，各改一个参数（学习率三档、batch 三档），**六种改法全部比 681.16 差**。
- **C 包 10 轮，链式带回退**：r09 被拒后回到 r08，r10 是对 r08 的确认（权重与 r08 相同），如实记录"这一轮没有得到更好的结果"，不是新模型。

校赛阶段平台只发一次数据，我们手里只有 batch1 能训、batch2 能看分。所以这 26 轮**每轮用的都是同一份 445 条 batch1，验证集始终是那 1244 条 batch2**（`tools/round_runner.py:146-147` 固定传入）。它证明的是**机制在固定数据上不会自伤**——评估门该拦的拦住了、该放的放过了——不是"跨批次漂移自适应"。真正的跨批次对抗要等企业赛：那时第 2 轮下发的 batch2 是训练数据而非验证数据，五环才第一次跑在"数据真变了"的路径上。

**关于 A 包那 +0.7pp，必须先说清它有多可信。** n=1244、Macro-F1≈0.72 时，bootstrap 标准误约 **±1.3pp**——**+0.7pp 落在噪声带内，不能称为"提升"**。正确的说法是"**与基线无显著差异**"。

三件事值得单独说。

**第一，真正有说服力的证据是负向的，不是正向的。** 十轮里八轮被评估门回退：多训 20 轮 −0.70pp、加大学习率 **−6.43pp**、减小 batch **−4.11pp**、bs256 −0.67pp、continue10 −0.84pp。唯一两次接受是 `lr=0.0015`（+0.48pp）和第一次小幅续训（+0.22pp）——**两者都在噪声带内**。

所以我们不说"我们调出了更好的模型"，说的是：**在 A 包上，"多动"有明确的、可重复的破坏性（最狠 −6.43pp），而"少动"的收益测不出来。** 掉分幅度与动作激进度单调相关：`lr_hi` > `bs64` > `continue20` > `bs256`，这给出了一张风险排序表。

**这个判断的适用域要先划清**：它成立于"**只能拿旧批次训练**"这个条件，不是"更好的训练方式不存在"。第四节末的 focal 实验把这条边界画了出来——同批次内切分 0.6880→0.8871，但评测的训练数据（batch1）与评测数据（隐藏流）不同分布，跨批次时同样的替换是 0.7226→0.7133。所以"多动不如少动"是被数据条件约束住的结论，不是我们没试过别的。

**同一件事的第四条证据：一个外部方案在我们这里的复现。** 我们拿到过一份公开实现，报告称 b1→b2 能到 **0.7475（+3.35pp）**、9 批滚动均值 0.84。它的核心是三项：逐样本 robust 标准化 + SupCon 对比学习 + 马氏距离原型头。我们逐项移植进官方框架，结果是：

| 移植到哪一步 | macro-F1（b2） | 相对官方基线 |
|---|---|---|
| 官方 CE（基线） | 0.7140 | — |
| + 逐特征 robust 标准化 | 0.7215 | +0.75pp（噪声内） |
| + 逐样本 robust 标准化 | 0.6806 | **−3.34pp** |
| + SupCon（加在 6 维 logits） | 0.7231 | +0.91pp（噪声内） |
| + SupCon（加在 32 维隐层） | 0.7100 | −0.40pp |

**+3.35pp 没能复现，最好只有 +0.91pp。** 根因是**起点不同**：那份实现的 0.7475 是**随机初始化、从头训**出来的；而我们受 `TRAINING_GUIDE.md` 约束必须 `--from-baseline`，权重已经被官方 CE 目标塑造过——SupCon 在这之上只是加了一项正则，不是重新塑造表征。

**这条比"我们试过 SupCon 没用"更有分量**：它说明在"必须从 baseline 出发"这条硬约束下，一大类依赖"从零学表征"的方法，其空间被结构性锁死了。顺带一个反直觉的发现——SupCon 加在 6 维输出上比加在 32 维隐层上好 1.3pp：这个任务只有 6 类且在输出层已近似线性可分，表征层再做对比学习没有额外信息可挖，反而干扰分类头。详见 `docs/supcon移植实验.md` 与 `docs/输入标准化对照.md`。

**我们没有采用它**，尽管 +0.91pp 是这一系列里最好的数字。理由：它仍在噪声带内（±1.3pp），而改反传逻辑会让 `checkpoints_trained/A.npz` 变化，牵连三条迭代线、作品文档每一处引用、SwanLab 全部记录都要重做。**用一次全域重算换一个测不出来的收益，不划算。**

这个判断还有第三条独立证据：把训练集内部切 20% 当验证集来选配置，选出的"最优"（多训 40 轮）在 batch1 内部涨 4.37pp，到公开验证集上掉 1.21pp——**内部验证集量的是过拟合程度，不是泛化能力**（详见 `docs/a_internal.md`）。

**第二，B 包六次独立尝试全部比官方权重差，我们选择不动。** 六次都从同一个官方起点出发、各改一个参数，没有一次让 RMSE 变小（最小 +3.6，最大 +33.8）。原因不是漂移：B 包训练集是 9 根轴承、验证集是 3 根**完全不同**的轴承（重叠为零，其中 Bearing3_4 一根就占验证集 90%），问题在跨个体的泛化，续训只会让模型更贴着那 9 根训练轴承。

更关键的一条是从官方 `history.jsonl` 里读出来的：**官方公布的那个 checkpoint，恰好是它自己训练过程中最差的一轮**。15 个 epoch 的验证 RMSE 是 580.15 → **567.15（第 2 轮，最好）** → 590.93 → 645.42 → **681.16（第 15 轮，公布值）**，而训练 loss 从 0.674 单调降到 0.10。也就是说权重已经明显过拟合，**从它出发续训，只可能更过拟合**——六个动作全负是这条曲线上的必然，不是我们的规则太保守。

**但我们不声称"能把它修到 567"。** 选第 2 轮需要看验证集 RMSE，而评测时没有验证集标签；在公开验证集上挑 epoch 就是刷分，正是我们拒绝的做法（见 §四）。

**最终交付的是官方权重本身。** 十轮全部 `noop`，候选就是把父检查点原样复制，`steps/epochs` 仍是 15/825，`metadata` 一个字段都没动——这一点平台可以直接核对 sha256。

我们**做过**输出层收缩实验，但没有提交。原因是平台审核：v3 提交被判 `noncompliant`，原话「请基于官方 baseline 及平台提供的父检查点实现真实续训，不要从头训练其他模型」。收缩是在权重文件上做确定性变换、`steps` 不变，属于手工改造，不是续训产物。我们撤回，接受 B 与基线同分。下面是这个实验的记录，标为"评估过、未采用"。

模型在验证集上基本不随输入变化——逐根看组内斜率是 `Bearing1_4` **0.01**、`Bearing2_4` **0.00**、`Bearing3_4` **−1.05**。**它没有在预测剩余寿命，只在预测"这根轴承处于什么水平"。** 所以输出里那部分"随输入变化"的分量，贡献的是噪声而不是信息。

收缩就是把输出层整体向训练集中位数拉：

```
w2 ← α·w2,   b2 ← α·b2,   target_mean ← α·target_mean + (1−α)·758
```

α=1 是官方原样，α=0 是恒输出 758（训练集中位数）。**注意常数必须混进 `target_mean`，不能加到 `b2`**——`b2` 在无量纲的 z 空间，加 758 会被 `target_scale=785` 放大成几十万分钟的偏置（我们第一版就这么写错过，RMSE 直接到 29 万）。

| α | 总分 RMSE | 1_4 (122 条) | 2_4 (42 条) | 3_4 (1,515 条) | **最坏一根** |
|---|---|---|---|---|---|
| 1.00（官方） | 681.16 | 242 | 391 | **711** | **711** |
| 0.75 | 599.94 | 328 | 458 | 620 | 620 |
| **0.50（提交）** | **534.08** | 442 | 543 | 540 | **543** |
| 0.25 | 488.63 | 567 | 637 | 477 | 637 |
| 0.00（纯常数） | 470.78 | **698** | **738** | 437 | **738** |

**为什么这个实验选 0.5（仅供参考，未提交）**

这条选择有留一交叉验证支撑：每次拿两根学 α、在第三根上考，"每轮学着定 α"平均 **715.6**，比固定 0.5 的 **508.2** 差了 207。原因是 α 的最优值取决于"这批里哪根轴承占多数"，而这件事预测时看不见。**所以我们不拟合 α，固定它。**

**这不是漂移对抗，不要归到那一类。** 它没有监测、没有触发、对数据变化没有任何反应——它是"识别出这个包不该动"之后的**模型选择**，不是"监测到漂移之后的动作"。B 包的问题从头到尾不是漂移，是**跨个体泛化**（训练 9 根、验证 3 根、重叠为零）。前一种定位会误导人去给 B 设计漂移检测，那从一开始就是错的。

**第三，C 包有真实增益且来回震荡。** 十轮里六次被接受、四次被回退，中间 `lr_hi` 一次就降了 0.57，但后面 `bs64` / `bs256` 又反弹回去。第 10 轮是对第 8 轮的确认（权重完全相同），如实记为"这一轮没有得到更好的结果"。说明 C 包还有余量，但也说明**没有评估门的话，那六次接受里有几次是在追噪声**。

## 四、我们否掉的方案（这部分可能比结果更有价值）

赛题评分里有"方法设计与技术路线"一项。我们把试过并证伪的东西也写出来，因为**知道什么不管用，和知道什么管用一样重要**。

**TTA（测试时自适应）不是第四种动作。** 三条路线都实测了：动权重（熵最小化 + 正例率锚定）让 F1 涨 1.08pp 但 **AP 一动不动**——涨的是阈值碰巧对齐，排序能力没变；只换输入标准化统计量**掉 3.1pp**，因为它把"特征整体平移"这个真实的漂移信号当噪声抹掉了；唯一有效的是只动阈值，而那正是我们已经有的校准动作。

**A 包的 Acetaldehyde 在合规前提下无解。** 这一类在验证集上召回为 0（109 条里 108 条判成 Ethanol，平均置信度 0.958——"自信地错"）。试了六种救法全部无效：类别加权（权重给到 2.47）、过采样到每类 90、修正官方 shuffle、加偏置、输入归一化、以及组合。原因是**方向翻转**：batch1 上训一个 Acetaldehyde vs Ethanol 的二分类器，到 batch2 上跨批次 AUC 是 **0.1137**（分反了），而 batch2 内部五折交叉验证 AUC 是 **0.9939**。同一份特征，两个批次里这两个类别的相对位置互换了。加偏置是平移、重加权是改梯度幅度、过采样是复制样本——**都换不了方向**。

要救只能拿 batch2 重新对齐坐标系，而那是 `TRAINING_GUIDE.md:32` 明令禁止的。所以我们接受它，并在文档里写清楚为什么。

**官方 `baselines/model.py:113` 有个 bug。** `SeedSequence([seed, epochs])` 里的 `epochs` 是常数 20 而不是轮次序号，导致 20 个 epoch 的样本顺序完全相同。我们验证过（连续三次采样前 8 个下标都是 `[348 440 213 403 33 24 28 400]`）。修正它反而掉 1.1pp，所以我们保留了官方行为，只把这个发现写进文档。

**"在线无标签自适应"整条路走不通。** 这一条是在**预研阶段**（官方数据到手前，我们自己构造的工业漂移流）测出来的：只用分布信号的 `H_nolabel_dist` 组 F1 **0.7804**，低于冻结基线 **0.8065**——低于基线意味着不满足硬门槛，是出局不是降级。所以最终方案里，所有决策都建立在"延迟到达的标签"上，没有纯无监督的自适应。

**无标签的"陌生度"能报警，但不能定位。** 窗口级 PSI 之外，我们还试了逐条算：取模型隐层 32 维，算每条样本到六个类中心的距离（类中心由 batch1 算出，合法）。batch2 的中位距离是 batch1 的 **2.1 倍**（1.089 → 2.341），不需要标签、也不用攒够一个窗口；首次连续 3 条超阈值出现在**第 6 条**，比 PSI（要攒 100 条）早约 94 条。

但它测的是"像不像训练集"，不是"会不会判错"。逐类一张表最说明问题：

| 气体 | batch2 平均距离 | batch1 平均距离 | 准确率 |
|---|---|---|---|
| 乙醇 | 3.216 | 1.376 | 0.963 |
| **氨气** | **3.118（最陌生）** | 1.399 | **1.000** |
| 乙醛 | 2.681 | 1.325 | **0.000** |
| 丙酮 | 2.127 | 1.171 | 0.992 |

**氨气最陌生却全判对，乙醛全错却只排第三。** 我们原以为能靠"到预测类中心的距离"与"到最近类中心的距离"之差抓出"自信地错"，实测这个差**恒为 0**——模型选的中心永远是几何最近的那个，它错的时候不是选错中心，而是那个中心底下混进了别的东西。

而且"早"有一半是运气：batch2 第一块正好是乙醇，而乙醇是这批漂得最狠的类（距离是 batch1 的 2.3 倍）；换成从丙酮开始（报警率只有 10%）会晚得多。

结论：这个信号能回答"这批数据整体有多新"，不能回答"哪一类坏了"，更不能回答"该不该动"。而"有新数据就每轮都训"这个策略本来就不需要判据，所以它没进主路径，只作为数据体检工具记录在 `docs/a_embedding_distance.md`。

**大模型当决策者：我们做出来了，也实测了，结论是不划算。**

不是"没做"，是做完之后选择不用。预研阶段我们实现了 `--policy {rule, llm, hybrid}` 三种可切换的决策器，接的是校内真实的端点上真实模型，跑了四组：

| 决策器 | F1 | 调用次数 | token 消耗 |
|---|---|---|---|
| 纯规则（最终采用） | 0.8208 | 0 | **0** |
| 纯 LLM（27B） | 0.8208 | 21 | 8,993 |
| 混合（27B，规则兜底） | 0.8208 | 4 | 1,718 |
| 纯 LLM（35B） | 0.8190 | 21 | 9,260 |

**四组差 0.18pp，在噪声内；最硬的证据是 21 个窗口的动作序列逐位相同**——给定那 14 个无标签证据字段后，这道题只有唯一解，LLM 没有额外信息可用。成本侧：system prompt 占 8637/8993 tokens（约 411 tokens/窗口），completion 只占 4%。

需要标注适用范围，而且要说到底：**这组数字来自预研阶段的自构造流，不是官方三包。**

更关键的是，**这份预研数据被设计得足够简单，使得规则也能解**——它的标签是线性 logit 生成的 12 维问题，一个 13 参数的逻辑回归就能到 0.82。在这种数据上，换 27B 做决策本来就不该有差别；问题不在模型不够强，而在任务没有难点。所以这个实验只能证明"**在规则已经够用的任务上，LLM 不带来增量**"，不能证明"任何任务上都不带来增量"。我们不把前者说成后者。

官方数据上确实有两处值得验证，**我们没有做**：

1. **归因**。A 包是混杂的：类别占比剧变（Acetone 15.7%→42.8%）、标签漂移、还有类间挤压（Ethanol 样本量从 90 涨到 164，分布变宽把 Acetaldehyde 罩住）。规则靠两条 PSI 的比值，能算出 `covariate`，但说不清"是浓度分布变了还是批次配方变了"。
2. **判断该不该动**。A 包最反直觉的事实是重训会把宏 F1 从 0.704 打到 0.166（准确率反而涨到 99.6%）。规则靠预设阈值判断"别动"；如果要更早看出来"这 800 条里 Acetone 占一半，直接重训会塌成单类"，那需要另一类推理能力。

第 2 条我们在 11-15 补做了，见下。

### 官方 A 包上复测：LLM 决策者比规则差 8pp

A 包 1689 条切 17 窗（每窗 100 条），三种决策者**吃同一份 14 字段证据**，只换"谁拍板"；动作真执行（校准 = logit 偏置调整，重训 = 全批量 SGD 1 epoch），最后在整个 1244 条验证集上算宏 F1：

| 决策者 | 验证集宏 F1 | 相对冻结 | 重训次数 | 校准次数 |
|---|---|---|---|---|
| 冻结（不决策） | 0.7210 | — | 0 | 0 |
| **规则（采用）** | **0.7256** | +0.46pp | 6 | 2 |
| 混合（规则兜底） | 0.7126 | −0.84pp | 6 | 5 |
| **LLM（27B）** | **0.6403** | **−8.07pp** | 2 | 8 |

机制：**LLM 明显更保守**——它只主张 2 次重训（规则 6 次），把大量本该重训的窗口改判成校准。而校准是"用当前 100 条的预测分布去对齐参考分布"，样本太小、估出来的偏差本身是噪声，累积 8 次就把模型推偏了。最直接的对照是：规则与混合**都重训 6 次**，混合多做 3 次校准，就掉了 1.3pp。

**注意不要过度解读**：规则那 +0.46pp 同样落在噪声带内（±1.3pp），所以正确的说法不是"规则更好"，而是"**规则不更差，而 LLM 明显更差**"。−8.07pp 远超噪声，这一条是稳的。

四条局限必须一起说：① 这组实验里 `retrain` 用了标签，模拟的是离线十轮那一侧、不是在线推理；② 只有一条流 17 窗，不构成统计显著；③ 校准的实现（logit adjustment）是我们自己定的，换一种可能不同；④ 提示词没有为大模型专门优化。

在官方三包上，这个问题甚至不成立——推理期是零状态的纯前向（见第二节），没有任何钩子可以让 LLM 介入，"用不用大模型决策"在推理侧根本不是一个可选项。

### 一个只在"有新批次数据"时才成立的解

既然 Acetaldehyde 是最大的一块损失，我们把它单独查到底。最后一个怀疑对象是损失函数——类别极度不平衡时，交叉熵天然偏向多数类，而 focal loss 是专门治这个的。

**在官方口径下（batch1 训、batch2 测），focal 无效**：

| 训练方式 | 宏 F1 | Acetaldehyde |
|---|---|---|
| 冻结 | **0.7210** | 0.00 |
| 普通 CE 20 epoch | 0.7226 | 0.00 |
| focal γ=1 / 2 / 3 | 0.7133 / 0.7013 / 0.6919 | 0.00 |

γ 越大越差——因为 batch1 里 Acetaldehyde 只有 30 条，focal 只是"更用力地学这 30 条"，学不出它在真实数据里的形态。

**但把训练集换成同一批次的数据（batch2 自己切 70/30 分层抽样，870 训 / 374 测），同样的数据、同样 20 epoch，只换损失函数**：

| 训练方式 | 宏 F1 | Acetaldehyde |
|---|---|---|
| 冻结 | 0.6818 | 0.00 |
| 普通 CE | 0.6880 | 0.00 |
| **focal γ=1** | **0.8871** | **0.96** |
| focal + 类别加权 1/√freq | 0.8856 | 0.94 |
| focal + 过采样 5 倍 | 0.8813 | 0.93 |

不只是救回小类：Ethanol 0.67→0.91、Ethylene 0.93→0.97，**所有类都变好**——这是"边界被重新划对"的特征，不是"拿一个类换另一个类"。

**这个 0.8871 不能提交**：它用 batch2 切成 870 训 / 374 测，而 batch2 就是 `public/validation.jsonl` 的全部内容——这一下同时踩了两条红线：`TRAINING_GUIDE.md:9`（验证集不要合并进训练集）与 `:32`（验证集不能参与拟合任何统计量，标准化参数会被重估）。它只证明一件事——病根不在损失函数，而在"两个批次的 Acetaldehyde 不是同一个东西"。

它给出的是企业赛路线：数据分批下发、每批带标签，那么"**从 baseline 出发 + focal + 只用新批次数据训**"可能把崩掉的类救回来，且父检查点仍是 baseline、父子链不断。三个前提缺一不可：新批次数据量要够（870 条能到 0.8871，200 条未必）、要有标签、要改 `baselines/train.py` 的损失函数。企业赛第一批数据下来后做一个对照（CE 续训 vs focal 续训）就能定论。

**这也解释了我们的动作空间为什么不够**。四个动作（none / calibrate / retrain / rollback）能治的是"边界偏了"，治不了"特征不够""结构不够""损失函数不对"。后三类里只有损失函数这一项**合规且未试**——它在官方口径下已被证明无效，所以不是我们偷懒，是这条路本身走不通。

所以我们的口径是：**默认用规则（成本 0），`--policy llm/hybrid` 保留为可切换项。如果赛道要求必须由大模型驱动，改一个参数即可，不需要改代码。**

## 五、工程上做了什么保证

**镜像**：

- `python:3.11-slim` + 本地 wheel 离线装 numpy，`docker build --network none --no-cache` **8.8 秒**
- 345 MB（限制 2 GB），无 GPU、无网络依赖
- 三包端到端：A 1244 行 / B 1679 行 / C 23049 行，**行数一进一出完全对齐**，无丢行、无乱序
- 输出格式与官方 `predict.py` 逐字节兼容：分类 `{"outputs":[{"label","score"}...]}`、回归 `{"outputs":{"value":x}}`

**两个会毁掉整份评测的 bug，我们自己找出来并修了**：

1. **UTF-8 BOM**：Windows 导出的文件常在开头带一个 `\ufeff`，它不是空白字符、`.strip()` 删不掉，`json.loads` 会直接抛 `Unexpected UTF-8 BOM`。BOM 只在文件开头出现一次，所以**受影响的是首行**——首行会落入兜底分支、输出六类各 1/6 的均匀分数（等于这一条随机猜）。修复方式是在 `json.loads` 之前 `lstrip("\ufeff")`，修复后带 BOM 与不带 BOM 的输入**逐位相同**（实测：A 包全量 1244 行，两种输入都是 macro-F1 0.7210）。
2. **坏行杀进程**：任何一行解析失败会让整个进程 `exit 1`，**后面所有正常行全部丢失**。改成单行失败只记 stderr 并输出兜底答案，保证输入行数 = 输出行数。

这两条都不会让分数变高，但前者会让首行静默变成一次随机猜、后者会让整份输出被截断——两种都是"跑完了、看起来成功了、结果是错的"，比直接崩溃更难发现。

**状态按任务分桶**：三包共用一个进程，A 的诊断状态如果串到 C 上，会让 C 拿到完全错误的决策。代码里用 `state.setdefault(task, new_state())` 强制隔离，并用混合流实测验证过。

### 数据来源核对，以及一条合规声明

我们把官方 A 包和 UCI 原始数据集逐条比对过：`public/train.jsonl` 的 445 行与原始 `batch1` **445/445 逐条一致、顺序相同**，`public/validation.jsonl` 的 1244 行与 `batch2` **1244/1244 逐条一致、顺序相同**（原始 13910 行中无重复特征向量，所以匹配唯一确定）。也就是说，官方没有打散、没有抽样、没有改标签，就是把两个批次整段拿来当训练集与验证集。

由此可以确定隐藏测试流就是 `batch3–batch10`（12121 行，正好是原始数据的剩余全部），而且"十轮"与这十个批次一一对应。

**因此我们明确声明**：本报告中所有用到 `batch3–batch10` 的实验（附录 A 的扩展数据验证、附录 B 的滚动留一批），**只用于离线验证方法与结论，不参与任何提交权重的训练**。提交的 checkpoint 只用了官方 `train.jsonl`（即 batch1）。跑完这些实验之后，我们没有回头修改任何默认配置。

这条核对顺带解释了官方基线从 train 的 0.9558 掉到 validation 的 0.7140 的真正原因：不是模型退化，而是**验证集的类别分布与训练集差了一个数量级**——Acetone 从 70 条涨到 532 条（7.6 倍），Toluene 从 74 条掉到 5 条（小 15 倍）。

## 六、我们没做到的

按"宁可低分，不许虚假"写：

1. **"越用越会调"没有证据。** 评分表这一项要的是"同一类漂移反复出现时，恢复所需轮数递减"。我们只有一条迭代线，凑不出重复事件，拿不到这个分。我们做到的是"在合适时机停手"，不是"越用越聪明"。
2. **归一化增益 G 算不出来。** 分母要求"全量重训能好多少"这个天花板，而官方没有定义"阶段"是什么。我们改报绝对增益和单位成本增益，不自己造公式。
3. **A 包的 Acetaldehyde 仍是 0。** 见第四节。这一类的上限锁死在 0，A 包剩余可优化空间经盘账不足 3pp。
4. **校赛只发一批数据，所以提交物里只有"机制验证"，没有"跨批自适应"的实证。** 赛题真正的十轮形态要等企业赛。作为弥补，我们自行补了一组"用过去预测未来"的滚动留一批实验（附录 B），那一组才是企业赛的真实形态。
5. **轴承与发动机两个包只跑了续训，没有做更结构性的改造。** 因为改结构要切断 `parent_checkpoint_sha256` 的父子链，等于放弃"续训"的叙事，代价高于收益。
6. **归因的准确率只在原型阶段验证过，官方数据上没有。** 95.2%（20/21 个报警窗）那个数字来自我们自造的合成漂移流。官方 A 包的数据**按类别成块排列**（batch1 的 445 条只有 9 段，Acetaldehyde 是独立一块 30 条），按 100 条切窗会把不同类别互相比较，算出来的 PSI 不反映漂移——因此我们拒绝在 A 包上做窗级归因验证，也就没有"真数据上的归因准确率"这个数。真数据上能拿出的只有两条：批次级 PSI（见下）与逐类 F1/AUC（证明"该重训"）。
7. **"监测"在 A 包上几乎是恒真的。** 实测官方十批两两相邻的特征 PSI 中位数在 **0.44–2.80** 之间（batch1→batch2 是 0.69，最大一对 b7→b8 是 2.80），而行业惯例 0.25 就算显著漂移——**每一对都是阈值的 2–11 倍**，且 128 个特征里 84%–100% 超标。所以在 A 包上"检测到漂移就调整"和"每轮都调整"是同一件事。**这不是监测没做，是监测给出的结论就是每批都该动**；同一套机制在 B 包（训练/验证同分布）上判的是"不该动"，六轮全拒——那才是它作为判据的价值。
8. **策略参数（噪声带、平台期长度）是固定值，没做在线估计。** 在线估计需要同方向多次重复实验的方差，而动作空间在 3–4 轮内即被穷尽（R1 判死后不再尝试），样本量不足以支撑估计。**在样本不足时用估计值替代先验，是把噪声当信号。**
9. **动作空间只有 epochs 维度，漏了 learning-rate——而 lr 恰恰是 A 包上唯一有效的旋钮。** 赛时 `ACTIONS` 只有 `noop` / `retrain_20` / `retrain_10`。补测（从官方 checkpoint 起跑）：

    | 配置 | macro-F1 | vs base |
    |---|---|---|
    | base（lr=0.003, 20ep） | 0.716180 | — |
    | lr_lo（0.0015, 20ep） | 0.722187 | +0.60pp |
    | lr_lo（0.0015, 10ep） | 0.717688 | +0.15pp |
    | **lr_hi（0.006, 20ep）** | **0.722977** | **+0.68pp** |

    **从官方权重直接训，`lr_hi` 比 `lr_lo` 还高**；而固定表里 r06 的 `lr_hi` 只有 0.6566，因为它接在 r03（已训过一轮）后面。继续第二轮，三种续法全崩：`lr_hi→lr_hi` 0.667708（−5.5pp）、`lr_hi→lr_lo` 0.693492（−3.0pp）、`lr_hi→base` 0.667708（−5.5pp）。⇒ **A 包 445 条上"续训一轮见顶、第二轮必崩"，与哪个 lr 无关；固定表里 lr_lo / lr_hi"一好一坏"不是 lr 有好坏，是它们接的父模型不同。**

    为什么明知 +0.68pp 也不改：① 链上拿不到（第二轮必崩，0.7230 维持不到第三轮）；② 0.7210→0.7230 只 +0.2pp，而 A 包 bootstrap SE 是 **±1.27pp**——同一把尺子不能一边把 +0.48pp 判为不显著、一边为 +0.2pp 重打镜像；③ 改 `ACTIONS` 要重跑 records、重打镜像、替换文档里所有 0.7210。**这不是"没想到调 lr"，是"调了、量了、发现它只在第一轮有效，而第一轮不在策略的可选位置上"。**

    顺带记两个能主张的数字（`docs/省轮次对照.md`）：假宿主逐轮看（`harness_sdk/fake_host.py A 6`），策略**第 5 轮**进入 `noop` 并保持，固定表第 5–10 轮仍在试，**少耗 4 轮**、终值相同；而那 6 轮并非"只是花时间"——r08 `0.7143`、r09 `0.6861`、r10 `0.6697` 是**真的训出了更差的模型**，只是被门拦下没上线。
10. **比"动作集太窄"更根本的一层：R1 判据在噪声带大于真实失败时，等于"永不判死"。** 用 `out_chain_a` 的历史做回放（`tools/exp_policy_rounds.py`），**S1（现状三个动作）与 S2（额外加入 `lr_lo`）结果完全相同，都是 0.71618**：`retrain_20` 的两次失败是 −0.70pp，落在 ±1.27pp 噪声带内，而 R1 要求"连续两次**超带**退步"才判死，于是它永远占着候选第一位，`lr_lo` 根本轮不到。更合理的判据是"**连续 2 次带内且为负 ⇒ 换方向**"，或按"已试过且未改进"降权。这一条比补 `lr` 维度更根本，同样**不改**（要改判据 + 重跑 + 重打），记为已知局限。

    **它同时把策略的定位说清楚了**：这套策略不是"能自动找到更好的动作"，而是"**能在噪声里识别出'再试也没用'**"——而在 A 包这个数据上，它连这件事都做得不够好（0.71618 vs 固定表 0.72099）。答辩若被问"你们的策略真的有效吗"，这是标准答案。

### 附：扩展数据验证（正反两面都写）

赛题原文的加分项里有"使用推荐扩展数据集完成扩展验证"。我们做了，但它的说服力必须限定，所以单列在这里而不是混进第三节。

**做法**：把原始数据集里官方没公开的 batch3–batch10 当作"企业赛陆续下发的新批次"，逐轮续训（从 batch1 出发，每轮追加一个批次），同时跑 CE 与 focal 两臂，固定用 batch2（1244 条）测。

**结果**（宏 F1，CE 臂）：

| 轮 | 训练批次 | 累计样本 | 宏 F1 | Acetaldehyde 召回 |
|---|---|---|---|---|
| 0 | [1] | 445 | 0.7140 | **0.00** |
| 1 | [1,3] | 2031 | **0.9191** | **0.96** |
| 2 | [1,3,4] | 2192 | **0.9678**（峰值） | 0.99 |
| 8 | 全部 | 12666 | 0.8761 | 0.99 |

三条能站住的：

1. **Acetaldehyde 的问题纯粹是数据覆盖**。不改结构、不改损失函数，只是多给一个批次，召回从 0.00 到 0.96。这和第四节的"方向翻转"是同一件事的两面——不是学不会，是没见过足够多的样本。
2. **评估门在真漂移上值 9.2pp**。无门时分数从峰值 0.9678 一路滑到第 8 轮的 0.8761；有门就钉在峰值上。这是"该不该动"第一次在真实分布上被量化，比合成流上那个 +1.93pp 硬得多。
3. **峰值出现在第 2 轮、累计 2192 条**。不需要攒很多数据，企业赛前两批就可能到位。

两条必须同时说的限制：

- **方向是反的**。训练集含 batch3–10、测的是 batch2，等于"用未来预测过去"。企业赛是"用过去预测未来"，泛化难度更高。所以 0.9678 **不是**提交预期。
- **不能拿它反向调参**。batch3–10 很可能就是隐藏测试流（行数对齐：batch1 = 445、batch2 = 1244 与官方包一行不差，剩下 12 121 行正好是这八批）。用它出结果是一回事，用它改配置就是变相过拟合隐藏集。**我们跑完之后没有回头改任何默认配置。**

预注册与实际结果的偏差也如实记：跑之前我们赌"focal 会赢"，实际 focal 只在第 1 轮领先 1.3pp，峰值反低 1.7pp——因为这个场景的主矛盾是样本量（445→12666），不是类别不平衡，focal 没有用武之地。

### 附二之1：官方权重在后续批次上会崩

既然 batch3–10 很可能就是隐藏测试流，我们干脆把官方 `checkpoint.npz` 直接在这八批上跑了一遍，看它自己会掉到哪：

| 批次 | 2（公开 val） | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---|---|---|---|---|---|---|---|---|---|
| 宏 F1 | 0.7140 | 0.5939 | 0.4893 | 0.5225 | 0.3228 | 0.3267 | 0.2664 | **0.1852** | 0.3806 |

**公开验证集 0.7140，到第 8 个月只剩 0.19。** 这一点很重要，因为它说明：**官方基线的 0.7140 是在最容易的一批上测的，隐藏流的真实难度远高于此。** 谁要是把自己的分数和 0.7140 比，比的可能根本不是同一件事。

同时它也是一条真正的机会：**基线在后续批次上会崩，意味着"跟上"就有很大的绝对增益空间**——这和我们前面"续训大多数时候是负的"并不矛盾，因为续训是在 batch1 上原地打转，而这里缺的是新批次数据。

### 附二之2：企业赛形态预演——滚动留一批（这一组才是真实的十轮）

校赛只发一批数据，所以我们自己造了企业赛的形态：**只用已经拿到过的批次训练，在下一批没见过的数据上测**。第 1 轮 [1]→测 batch3，第 2 轮 [1,3]→测 batch4，……，第 8 轮 [1..9]→测 batch10。三种配方（累积全部 / 只用最近两批 / 只用最新一批），同一套超参，交叉熵。

**这个形态的关键是"永远落后一批"**：

```
第 N 轮开始
  手上有的标签：batch1 … batchN      （batchN 就是上一轮被考的那批，这一轮才拿到答案）
  要预测的：    batchN+1             （还没见过，没有标签）
  训练：        用 batch1..N
  提交：        新镜像 → 平台拿 batchN+1 去考 → 出分
```

所以每一轮我们都**能**拿到新数据（带真标签，不需要伪标签），但它永远是"上一轮被考的那批"；而我们要优化的那一批，永远是没标签的。**我们没有任何能直接反映"下一批会怎样"的信号**——手上最接近的东西，是"上一批考了多少分"，而它与下一批不同步。

这正是评估门在逻辑上不可能有效的根源（见下），也解释了为什么正确的策略是"别猜，每轮都用全部已知数据重训"。

**八轮均值**：

| 配方 | 均值宏 F1 | 相对冻结 |
|---|---|---|
| 冻结（只用 batch1，永不更新） | 0.3859 | — |
| **累积全部历史** | **0.7050** | **+31.91pp** |
| 只用最近两批 | 0.6745 | +28.85pp |
| 只用最新一批 | 0.5910 | +20.51pp |

逐轮（累积全部）：0.5976 / 0.6353 / 0.8028 / 0.5988 / 0.7851 / 0.7698 / 0.7558 / 0.6946（对应测试批次 b3–b10）。

三个能站住的结论：

1. **"该攒就攒"，而且能解释为什么。** 累积全部（0.7050）比只用最近两批（0.6745）高 3pp，比只用最新一批（0.5910）高 11.4pp。原因是**这批数据的漂移不是单向恶化，而是在几个状态之间来回摆**：
   - 相邻批次的 PSI 中位数：0.67 / 0.54 / 1.05 / 1.58 / **1.94** / 0.44 / **1.96** / 1.27 / 1.18——9 次换批有 7 次是剧烈跳变，是**阶跃**不是渐变。
   - 但"离 batch1 最远"的并不是最后一批：b1 vs b5 是 3.87、b1 vs b9 是 3.62，而 **b1 vs b10 只有 0.36**——最后一批的分布几乎回到了第一批。
   - 均值向量的余弦相似度全部在 0.89–0.999 之间，说明**方向没变，只是位置在摆**。
   
   一句话：**不是"一路变坏"，是"在几个状态之间往返"。所以正确的策略不是"忘掉旧的、只学新的"，而是"留着旧的、全都学"**——历史数据里存着将来还会遇到的分布。这也顺带说明，官方工具链那条"训练集 ≤128 MiB"的限制不是设计者疏忽，而是留给"数据选择"的一道真问题。
2. **没有灾难性遗忘。** 第 1 轮训练 445 条得 0.5976，第 8 轮训练 9066 条得 0.6946。学得越多越好，没有"学新的忘旧的"。这一点和我们最初在自构造流上看到的"滑动窗口救漂移段、害恢复段"（第四节）方向相反，原因是这里每轮都有**新批次的真标签**，而不是在旧数据上反复打转。
3. **冻结模型跨批次的泛化极差**（0.19–0.59，均值 0.386）——这是"必须续训"最直接的证据，也说明公开验证集那 0.7140 是个过于乐观的参考点。

一个反直觉的观察：**每轮崩掉的类不一样**。b3 崩 Acetaldehyde（召回 0.00）、b6 与 b9 崩 Toluene（0.00 / 0.01）、b10 崩 Ethanol（0.57）。所以不是"小类一定学不会"，而是"**这一批里稀有或形态特殊的那个类会崩**"——这比"某个类永远不行"更难对付，因为没有固定目标可以盯着。这也是我们在训练轮里坚持"逐类记录"而不是只看总分的实际原因。

focal 在同一组里也测了：8 轮 × 3 配方，与交叉熵**逐位相同**（唯一差异是 r3/last1 的 0.0029）。原因算出来了：focal 权重 w = u^γ⁻¹(u − γ·p_t·ln p_t)，在模型还欠拟合时 p_t 低、u ≈ 1，代入 γ=2 得 **w ≈ 0.995**，等于没加权。所以"focal 在这个任务上无效"的准确说法是——**5 个 epoch 不足以让模型进入 focal 能起作用的区间**，不是方向错。这条同时解释了第四节里"官方口径下 γ 越大越差"：γ 越大，欠拟合阶段被压的有效学习率越低。

**边界（必须一起说）**：这组数字不代表平台评测分会是 0.70——冻结臂只见过 batch1，天然吃亏，真实评测里各队起点不同；也不代表我们的归因模块有用，因为这组全程是**无条件续训**，没有走"该不该动"的判断。它证明的是一件具体的事：**当新批次带着标签陆续到来时，累积续训能把 8 轮均值从 0.386 拉到 0.705，且不遗忘历史。** 这正是企业赛要考的能力。

**顺带试过、并且失败的一个想法**：既然分布来回摆，那"保留历史上每一个模型、投票平均"是不是更好？我们拿 r01–r08 八个 checkpoint 做了概率平均，5 种加权方案，八批均值全部不如只用最新的 r08：

| 方案 | 均值宏 F1 | 相对 r08 |
|---|---|---|
| 只用 r08 | **0.8853** | — |
| 只取最近 3 个 | 0.8572 | −2.81pp |
| 按训练样本量 log 加权 | 0.8424 | −4.29pp |
| 等权全部 8 个 | 0.8304 | −5.49pp |

原因很清楚：**r08 是累积训练出来的，历史信息已经压进它里面了**；再和 r01–r07 平均，等于把更弱的旧模型重新拉回来稀释判断（b9 上最明显：r08 单独 0.987，等权后掉到 0.743）。所以"多留几个标准一起投票"这条路，在**累积训练**的前提下不成立——它适用于"每轮各自独立训练一个模型"的形态，而那种形态会因为某些批次缺类（batch3–5 的 Toluene 占比是 0%）而引入新问题。这一条记为"想过、算过、不采用"，复现脚本 `tools/exp_ensemble.py`。

复现：`python tools/exp_ext_rolling.py`（8 轮 × 3 配方 × 2 臂，约 6 分钟），结果在 `out_ext/roll_all.json`，逐轮逐类明细在 `docs/扩展验证.md` 第六、七节。

## 附：一句话

这个系统在三个包上做对的事只有一件——**在官方给定的训练配置下（`baselines/train.py` + 交叉熵 + 续训），判断"该不该动"比"怎么动"更重要**。A 包 10 轮里 8 轮该回退，B 包 6 次尝试全部该回退，C 包 10 轮里四次该回退。评估门拦下的那些动作，如果全部执行，三个包的总分会比"什么都不做"更低。

这个结论有边界，必须自己说出来：**训练数据与评测数据同分布（同批次）时，把损失函数换成 focal，Acetaldehyde 从 0.00 到 0.96、总分 0.6880→0.8871；两者跨批次时，同样的替换反而更差（0.7226→0.7133）。官方评测只给我们旧批次（batch1）的标签、隐藏流是新批次，属于后者——所以在可用的条件下，多动不如少动。** 边界钉在数据分布上，不是"有没有新批次标签"（拿到 batch2 标签去训、再拿 batch3 测，仍是跨批，focal 未必反转）。
