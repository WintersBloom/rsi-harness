# 整个流程的规范（合规清单）

> 依据：`out2.txt` 赛题原文、`cpu-a-guide-20261110-v1/TASK.md`、`TRAINING_GUIDE.md`、
> 平台 `/rules` 与 `/scoring-rulesets` 实测字段、首轮培训转写。
> 写这份的目的：**知道哪里可以自由发挥，哪里踩线就废**。

---

## 一、数据规范：三条隔离线

### 1. 输入里不许有"答案的影子"

| 允许进模型 | 禁止进模型 |
|---|---|
| `inputs.features`（A）、`inputs.settings` + `inputs.sensors`（C） | `answer` / `target` |
| — | `id`、`meta.source_batch`、`meta.source_index` |
| — | 完整寿命信息、阶段标签、隐藏标签 |

原文（`TASK.md` A）：

> `id`、`meta.source_batch`、`meta.source_index` 仅作追溯，不是参考模型输入。

**我们的对应**：`src/io_adapter.py` 只读 `t, segment, f0..fn, label`，`segment` 是自造的段标签而且只在"评估"时用，不进 `evidence`。这一条目前是干净的。

### 2. train / validation / hidden 三层不许串

- `public/train.jsonl`：**梯度更新只能用这个**
- `public/validation.jsonl`：只能用来"衡量改动"，**不能合并进训练集**
- 隐藏集：平台独立保管，包里不含样本、名单、答案

原文：

> 隐藏数据由平台独立保管，本包不包含隐藏样本、名单或答案。

**校验点**：`train.py` 会检查 train/val 的 sample id 不重叠。

### 3. 标准化参数只在训练集拟合

原文：

> 输入均值、标准差及回归目标缩放最初只在训练集拟合；续训沿用检查点状态。验证集和隐藏集不能参与拟合这些统计量。

**为什么重要**：如果拿验证集算均值方差，等于提前看了一眼未来。这是最容易被忽略的泄漏。

**我们的对应**：`checkpoint.npz` 里存着 `mean` / `scale`，续训自动沿用，这条天然合规。

## 二、训练规范：十轮工作区的真实含义

### 1. 十轮是"离线做十次实验"

平台字段：`workspace_suite.rounds = 10`

`records_policy` 原文：

> 工作区十轮记录：假设、代码变更、父模型与候选摘要、续训证据、验证指标和调用用量。

**每一轮要留下六样东西**：

| 记录项 | 我们怎么留 |
|---|---|
| 假设 | 这轮想验证什么（写进 stage 的 markdown） |
| 代码变更 | git commit + 变更说明 |
| 父模型摘要 | `train.py` 自动写进 `training.json` |
| 候选摘要 | 新 checkpoint 的 sha256 |
| 续训证据 | 累计步数增加、父检查点对得上 |
| 验证指标 | `history.jsonl` 逐 epoch 记录 |

### 2. 每轮输出必须是新目录

原文：

> 输出目录必须是新目录；**上一轮不会被覆盖**。

`train.py` 硬校验：`output must be a new directory; previous rounds are never overwritten`

### 3. 从"仍被选中"的模型继续

原文：

> 使用实际上一轮选定的检查点；**若平台没有采纳某轮候选，应从仍被选中的模型继续**。

意思是：不是线性往后接，而是"以被采纳的那条线为准"。

### 4. 改结构要显式迁移，不能冒充续训

原文：

> 改变网络结构、输入维度或任务时，需显式实现兼容的权重迁移，**不能将一个新模型声明为原模型续训**。

`train.py` 会拦：

```
resume hidden width must match checkpoint; changing the profile does not migrate weights
resume must preserve the checkpoint's random seed
checkpoint task, profile, feature schema or classes do not match
```

### 5. 本地不调用 PyTRiO

原文：

> 本地 CPU 基线不调用 PyTRiO。平台的 PyTRiO 模型与 Harness 用于阅读、修改和运行这些代码；**工业模型始终是这些训练代码产生的检查点**。

## 三、记录规范：SwanLab

| 要求 | 出处 |
|---|---|
| 必须用，按《实验记录规范》 | 培训 PPT Q4 |
| 记录对象是**工业模型（被训小模型）的训练过程**，不是 Harness 决策过程 | 首轮培训转写 |
| 至少**三次尝试迭代**：读三次历史 → 提假设 → 做实验 | 同上 |
| 必须**设为公开**（Public） | 同上 + 评审会逐条看 |

**SwanLab 记录 ≠ 跑分表**。评审要看的是"你读了什么、想了什么、试了什么、结果如何"。

## 四、提交规范

### 1. 镜像

| 项 | 要求 |
|---|---|
| 架构 | `linux/amd64` |
| 体积 | ≤ 2 GB（我们的 86 MB） |
| 网络 | 运行时**断网可跑** |
| 内容 | Harness + checkpoint + 依赖，**不含数据集** |
| 权重 | 不能把大模型权重打进去（只填模型 id） |

### 2. 平台必填项（九项）

1. 镜像归档
2. 模型类型（`base` / `trained`）
3. 训练记录链接（SwanLab，公开）
4. 源码仓库链接
5. **PyTRiO API Key**（校赛阶段是否必填待确认）
6. 作品文档（pdf / md / txt）
7. 记录完整性声明
8. 材料完整性声明
9. 审核说明

提交后有两步：`/validate`（校验）、`/trial`（试运行，10 次配额）。

### 3. 评测环境

| 项 | 值 | 出处 |
|---|---|---|
| CPU | 4 核 | 培训 |
| 内存 | 8 GB | 培训 |
| GPU | **无** | 培训 |
| 外网 | **断网** | 培训 + 规则 |
| 单次时限 | 21600 秒（6 小时） | 平台 `/rules` |
| token 预算 | 8,000,000 | 平台 `/rules` |
| 标注预算 | 9,628 | 平台 `/rules` |
| 评测模式 | batch | 平台 `/rules` |

## 五、合规红线（踩了直接不合格）

| 红线 | 后果 | 我们目前 |
|---|---|---|
| 读隐藏标签 / 用 `answer` 做输入 | 成绩作废 | ✅ 不读 |
| 把新模型说成续训 | 实验记录不认 | ✅ 未改结构 |
| 用外部 API / 联网 | 评测环境直接失败 | ✅ 默认零网络请求 |
| 用非指定大模型驱动 Harness | 违规 | ✅ 默认不用 LLM |
| 验证集参与标准化 | 数据泄漏 | ✅ checkpoint 带 mean/scale |
| 提交包超过 2 GB | 传不上去 | ✅ 86 MB |
| SwanLab 不公开 | 不排名 | ⚠️ 沙盒是私有的，正式项目要公开 |

## 七、校赛版最小合规路径

如果时间紧，按这个顺序做：

1. **跑满 A 包十轮续训**（每轮改一点，记录假设）→ 产出 10 个 checkpoint
2. **选最优的那个**，打包进镜像
3. **SwanLab 建正式项目**（公开），上传十轮记录
4. **写文档六件套**：设计论证、运行说明、实验记录说明、合规声明、技术报告、README
5. **提交试运行**（10 次配额，先跑 2 次验证链路）

**不做的事**：改模型结构、接 LLM、做软归因、实现 TTA。这些是加分项，不是合规项。

## 八、一句话

> **合规不是"少做"，是"把做过的每一步都留下证据"。**
> 平台不看你多聪明，看你能不能证明"这个 0.72 是我自己一步步训出来的"。
