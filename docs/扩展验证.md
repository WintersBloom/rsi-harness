# 扩展数据验证：用 batch3–10 模拟企业赛十轮

## 〇、预注册（跑之前写，2026-11-15 17:26）

**假设（≤200 字）**

预期：CE 续训在 batch3–10 上**先涨后跌**——前几轮因新批次带来新样本而略涨，后几轮因类别分布剧烈变化（Toluene 在 batch3–5 为 0%）而向多数类塌缩，总分跌回或低于 baseline。

若比较 focal 与 CE：**预期 focal 赢**，因为 batch3–10 的类别不平衡比 batch1 更极端，而 focal 正是针对这个。但若 focal 也塌缩，说明问题不在损失函数而在"批次间同类不是同一个东西"（与 batch1→batch2 的结论一致）。

判定**五环无效**的条件：8 轮里没有任何一轮使验证集分数高于 baseline，且"被评估门拦下的动作如果执行反而更好"——两条同时成立，则说明在当前动作空间里，五环的判断没有产生正价值。

**实验后不得据结果调整任何默认配置**（避免变相过拟合隐藏测试流）。

## 一、设置

| 项 | 值 |
|---|---|
| 数据来源 | UCI gas 原始 `.dat`（batch1–10，13910 条），用 `tools/exp_ext_prep.py` 转 jsonl |
| 对齐校验 | batch1 = 官方 `public/train.jsonl`（445 条，逐条特征相同）；batch2 = 官方 `public/validation.jsonl`（1244 条）——**已逐条比对通过** |
| 训练集 | 逐轮累积：r1 = batch1+batch3，r2 = +batch4，…，r8 = +batch10 |
| 验证集 | **固定 batch2**（1244 条），分数可与官方基线 0.7140 直接比 |
| 训练方式 | 官方 `baselines/train.py`，5 epoch，lr 0.003，bs 128；r1 用 `--from-baseline`，之后 `--resume`（保住 `parent_checkpoint_sha256` 链） |
| 两臂 | CE（原样） vs focal γ=2（只改 `model.py` 的梯度一行，不改结构/超参） |
| 预处理一致性 | 标准化参数（`mean/scale`）沿用 checkpoint 状态，**没有用任何验证集重新拟合** |

**一个必须写明的局限**：训练集包含 batch3–10，而它们很可能就是隐藏测试流。所以下面 0.9678 这个数字**不能当作"隐藏流上的预期分数"**——它测的是 batch2。本实验回答的是"**数据是不是瓶颈**"，不是"企业赛能拿多少分"。

## 四、CE vs focal 对照

| | CE | focal γ=2 |
|---|---|---|
| r1（首批新数据） | 0.9191 | **0.9317** |
| 峰值 | **0.9678**（r2） | 0.9510（r2） |
| 无门最终（r8） | 0.8761 | **0.9044** |
| 加评估门后 | **0.9678** | 0.9510 |
| 门值 | **+9.2pp** | +4.7pp |

**预注册的假设一半对一半错，如实记录**：
- ✅ "先涨后跌" —— 对
- ❌ "focal 会赢" —— 错。focal 只在 r1 领先 1.3pp，峰值反而低 1.7pp；它的优势是收尾更稳（0.9044 vs 0.8761）。

**解释**：batch3–10 的主要问题是**样本量**（12666 vs 445），不是类别不平衡。focal 治的是不平衡，所以在这个场景里它没有用武之地——和 batch1→batch2 那次结论一致（那里 focal 也无效，但原因不同：那次是"同类不是同一个东西"）。

## 五、结论

### 证明了什么

1. **数据是 A 包唯一的瓶颈**。加一个批次 +20.5pp，两个批次 +25.4pp；而我们之前在"只有 batch1"的条件下折腾了十几组超参，最多 +0.7pp。
2. **Acetaldehyde 有解，而且解在数据里**。不需要改结构、不需要改损失函数，把新批次喂进去，召回从 0 直接到 0.96。
3. **评估门值 9.2pp**。无门时从 0.9678 一路滑到 0.8761；有门则把峰值钉住。这是"判断该不该动"第一次在真漂移上被量化。
4. **企业赛路线可行**：每来一批新数据就续训，峰值出现在第 2 轮（累计 2192 条），说明**不需要等数据攒很多，一两批就能见效**。

### 没证明什么

1. **没证明在"真正没见过的未来批次"上也能涨**。本实验的训练集包含 batch3–10，验证集固定 batch2，所以它测的是"用未来数据回补过去"，不是"用过去预测未来"。
2. **没证明 0.9678 是企业赛的预期分数**。隐藏流如果真是 batch3–10 的后段，那这个数字是乐观上界。
3. **没证明五环的"归因"环节有价值**。本次每轮都无条件续训，归因模块没有参与决策——它只证明了"该动的时候动是有用的"，没证明"我们判断得对"。

### 对作品文档的影响

- 第六节"只在验证集验证过"这一条可以改成"已做扩展数据验证"，并引用本文。
- **但结论口径不变**：评测时拿不到新批次标签，所以这个 +20pp 的解**不能提交**。它证明的是"我们有能力用好新数据"，不是"我们现在的提交会涨 20pp"。

## 六、滚动留一批：真正的企业赛形态（2026-11-15 18:10 补）

上面那组实验（训练集递增、验证集固定 batch2）是"用未来回补过去"，比真实场景**容易**。企业赛的真实形态是：第 N 轮拿到 batch_N，用它训练，然后被**第 N+1 批**考。

所以补做"滚动留一批"：每轮只用**已经拿到过的**数据训练，在**下一批没见过**的数据上测。

### 6.1 设计

| 轮 | 训练用 | 测在 |
|---|---|---|
| 1 | batch1 | batch3 |
| 2 | batch1,3 | batch4 |
| 3 | batch1,3,4 | batch5 |
| … | … | … |
| 8 | batch1,3…9 | batch10 |

三配方 × 两臂：`full`（累积全部历史）/ `last2`（最近两批）/ `last1`（只最新一批），CE 与 focal γ=2。每轮从官方 baseline 出发（`--from-baseline`），5 epoch，seed 42。

| 2 | [1,3] | 2031 | b4 | 0.4893 | 0.6353 | 0.6353 | 0.6561 |
| 3 | [1,3,4] | 2192 | b5 | 0.5225 | **0.8028** | 0.7937 | 0.5525 |

这否定了"小类一定崩"的简单叙事——**崩的是"这一批里稀有或形态特殊的那个类"**，不是固定某一个。

### 6.5 结论

**证明了什么**

1. **在真·企业赛形态下，续训有效，且幅度很大**：8 轮平均 +31.91pp（0.3859 → 0.7050）。这是我们第一次拿到"敢当作企业赛预期"的数字。
2. **累积全部历史最好**（0.7050 > 最近两批 0.6745 > 只最新一批 0.5910）。⇒ 企业赛**不要只留最新数据**，该攒就攒。
3. **没有灾难性遗忘**：第 1 轮 0.5976 → 第 8 轮 0.6946，训练集从 445 涨到 9066 条，越训越好，没有"学了新的忘了旧的"。
4. **focal 完全无效**：8 轮里 focal 与 CE 的差异只有 0.0029（仅 r3/last1 一处），其余逐位相同。
5. **冻结模型跨批次泛化极差**：batch1 训的模型在 batch3–10 上只有 0.19–0.59（均值 0.386）。这才是"必须续训"的最硬证据。

**focal 为什么完全没差别（这比"focal 无效"更有信息量）**

focal 权重 $w = u^{\gamma-1}(u - \gamma p_t \ln p_t)$，其中 $u = 1-p_t$。当模型欠拟合时 $p_t$ 很低、$u \approx 1$，代入 $\gamma=2$ 得 $w \approx 0.995$——**几乎等于 1，等于没加权**。

所以不是 focal 方向错，是**5 epoch、小数据下模型根本没拟合到 focal 能发挥作用的区间**。这也解释了 batch1→batch2 那次 focal 无效（同样是欠拟合）。

**没证明什么**

1. **不代表平台评测分会是 0.70**。冻结在 batch3–10 上低（0.386），部分是因为它只见过 batch1；平台如果给足训练数据，基线不会这么低。
2. **不代表我们比别的队伍强**。这是"续训 vs 不续训"的对照，不是队伍间比较。
3. **归因模块仍未参与**。三轮配方都是无条件续训，没有"判断该不该动"的环节。

## 七、评估门在真实漂移下失效（2026-11-15 19:05 补，**推翻之前的 9.2pp**）

之前第五节说"评估门值 9.2pp"。**那个结论是循环论证，作废**：那组实验里验证集和测试集都是 batch2，用 batch2 判断、再用 batch2 打分，门当然"有效"。

在"预测未来"的真实形态下（验证集是旧批次、测试集是下一批），结论**反过来**。

### 7.1 三臂对比（8 轮，测试 = 下一批未见）

| 策略 | 8 轮均值 | 逐轮 |
|---|---|---|
| 冻结（只用 batch1） | 0.3726 | 0.598 / 0.499 / 0.431 / 0.321 / 0.314 / 0.269 / 0.182 / 0.367 |
| **无条件接受每轮更新** | **0.7050** | 0.598 / 0.635 / 0.803 / 0.599 / 0.785 / 0.770 / 0.756 / 0.695 |
| 有门（验证集 = 固定 batch2） | 0.5743 | 0.598 / 0.635 / 0.803 / 0.615 / 0.644 / 0.440 / 0.417 / 0.442 |
| 有门（验证集 = 全历史均值） | 0.3726 | 同冻结——第 2 轮就被锁死 |

**门在两种验证集口径下都是负收益**：固定 batch2 掉 13.1pp，全历史均值直接退化成冻结。

### 7.2 为什么

关键在 `ckpt × batch` 分数矩阵（完整表见 `out_ext/gate_sim.json`）：

| 模型 | b3 | b5 | b7 | b9 | b10 |
|---|---|---|---|---|---|
| v0（只见过 b1） | 0.594 | 0.522 | 0.327 | 0.185 | 0.381 |
| r3 | 0.825 | 0.803 | 0.644 | 0.417 | 0.442 |
| r6 | 0.827 | 0.825 | 0.997 | 0.732 | 0.698 |
| r8 | 0.830 | 0.825 | 0.994 | 0.987 | 0.695 |

**新模型在"旧批次"上的分数先升后降，但在"新批次"上几乎单调升。**

- 用 batch2 验：r3 达到峰值 0.9453，r4 就掉到 0.9400（差 0.0053，刚好过门槛），门锁死，之后一直用 r3。而 r3 在 b8/b9 上只有 0.44/0.42，r7 却有 0.95/0.99。
- 用全历史验：r1 在 batch1 上 0.9696（过拟合自己），r2 掉到 0.8995 就被拦。而那正是**开始泛化的第一步**。

**一句话：旧数据测不出"在新数据上会不会更好"，因为这两件事不同步。**

### 7.3 这对方案意味着什么

1. **"判断该不该动"在我们这个场景里是负价值**——只要新数据是真的、干净的，每轮都接受就是最优。
2. **评估门防的是"坏更新"，但这个数据集上没有坏更新**。所以门没有可用武之地，只有在数据被污染/批次回退时才该出场。
3. **"稳定性与抗遗忘 5 分"和"适应漂移"是同一个矛盾的两面**：任何真正适应新批次的更新，都会让某几个旧批次掉分（r4–r7 期间 batch2 从 0.945 掉到 0.867）。官方要求"历史工况保持率 ≥95%"——按这个数据看，**全绿几乎不可能**，除非放弃适应。

### 7.4 口径修正

- ❌ 不再说"评估门值 9.2pp"。
- ✅ 改说："我们设计了评估门，并在真实滚动场景下**证伪了它的价值**——8 轮里它把均值从 0.705 拖到 0.574。原因是旧批次分数与新批次表现不同步。这个负结果本身是设计依据：**没有可靠的在线验证信号时，把决定权交给'是否变好'的猜测，不如交给'每轮都用最新数据'的纪律。**"

### 结论

1. **去掉"从 baseline 出发"这条约束，成绩没有变好**：从头训 CE 20ep 得到 0.7140，与官方 checkpoint 续训的结果逐位相同 ⇒ 官方权重就是从头训 20 epoch 的产物，没有隐藏加成。
2. **SupCon 在从头训时反而有害**（−13.2pp），只有在已有 CE 权重旁边作为正则项才有微弱正作用（+0.91pp）。
3. **参考实现的 0.7475 未能复现**：在官方框架内按同样思路移植 SupCon，最好结果是 0.7231，差距无法用"从头训还是续训"解释。

一句话：**在合规约束下，这个方向的上限是 0.72；去掉约束也没有更高（0.7140）。限制我们的是任务本身，不是这条规则。**
