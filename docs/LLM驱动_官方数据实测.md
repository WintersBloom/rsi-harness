# 官方 A 包上：AI 驱动 harness 会更好吗

**结论：不会。在 A 包上，让 Qwen3.8-27B 参与决策比纯规则差 8.5 个百分点。**

这是第一次在**官方数据**（而不是我们自造的合成流）上做的对照，所以它比之前那份"四方对照"更有说服力——但也仍有明确局限，最后一节写清。

---

## 一、为什么之前那份对照不算数

11-15 早些时候跑过一组：纯规则 / 纯 LLM / 混合，F1 全是 0.8208，动作序列逐位相同。当时就写了"不可外推"，原因很简单：

- 那条流是**线性 logit 生成**的，13 个参数就能拟合到 0.82；
- 决策空间只有 4 个动作、判据是几条阈值；
- 模型已经把问题解完了，换谁拍板都一样。

用户当时一句话点破："那是我们自己编的数据"。这份文档就是补上这个缺口。

## 二、实验怎么做的

| 项 | 设置 |
|---|---|
| 数据 | 官方 A 包：`public/train.jsonl` 445 条（batch1）+ `public/validation.jsonl` 1244 条（batch2） |
| 模型 | `harness/checkpoints_trained/A.npz`（十轮链第 3 轮，官方格式） |
| 切窗 | 每 100 条一窗 → 17 窗（4 窗 batch1 + 13 窗 batch2，末窗 89 条） |
| 证据 | 与 `src/policy.build_evidence` 同一套 14 字段：level、drift_type、两条 PSI、预测主类占比、累计宏 F1、预算余量、重训/校准冷却…… |
| 判据 | 与 `src/attribute.py` 同一套比值规则，但特征 PSI 取 **128 维的中位数**（单维最大值在 A 包上被噪声占满：噪声底 max 2.42 vs median 0.112） |
| 噪声底 | batch1 内随机抽两组不重叠的 100 条，重复 20 次取中位 = **0.1546**；据此 level1=0.309、level2=0.618 |
| 决策者 | 规则（`RulePolicy`）/ 大模型（`LLMPolicy`，qwen3.8-27b，关思考）/ 混合（`HybridPolicy`） |

三者吃**完全相同**的证据，唯一变量是"谁拍板"。

## 三、三者拍出来的动作不一样

`none` = 不动，`cal` = 校准，`R` = 重训。

```
w   00  01  02  03  04  05  06  07  08  09  10  11  12  13  14  15  16
rule ·   cal ·   cal R   ·   R   ·   R   ·   R   ·   R   ·   R   ·   ·
llm  ·   cal R   cal ·   cal ·   cal R   ·   cal ·   cal ·   cal ·   cal
hyb  ·   cal R   cal R   cal R   cal R   ·   R   cal R   ·   ·   ·   ·
```

统计：

| 决策者 | 重训 | 校准 | 不动 | LLM 调用 | token |
|---|---|---|---|---|---|
| rule | 6 | 2 | 9 | 0 | 0 |
| llm | **2** | **8** | 7 | 17 | 7,339 |
| hybrid | 6 | 5 | 6 | 9 | 3,890 |

**大模型明显更保守**：它只主张了 2 次重训（规则是 6 次），大量改判为"校准"。而且有 5 次被安全闸拦掉（`llm_blocked`）——它想动，但冷却或预算不允许。

看单个窗的犹豫程度：w10–w14 这五窗，规则是 `R · R · R · R · R`（一路重训），大模型是 `cal · cal · cal · cal · cal`（一路校准），混合是 `R · R · R · R · ·`。

## 四、把动作真的执行一遍，谁更好

只比动作不看后果是不负责任的，所以每条序列都实际执行了：

- `none`：什么都不做；
- `calibrate`：logit 偏置校正 `bias += log(参考分布 / 当前预测分布)`，只用**预测**分布，不用标签；
- `retrain`：用截至当前窗的**全部带标签数据**做 1 个全批量 SGD epoch（lr 0.05）。

评分：在整个 1244 条验证集上算宏 F1（这是能和官方 0.7140 / 0.7210 对齐的口径）。

| 决策者 | 验证集宏 F1 | 相对冻结 |
|---|---|---|
| 冻结（不决策） | 0.7210 | — |
| **rule** | **0.7256** | **+0.46pp** |
| hybrid | 0.7126 | −0.84pp |
| llm | **0.6403** | **−8.07pp** |

**大模型最差。**

## 五、为什么它更差

不是因为"答错题"，而是因为**它选了一个在 A 包上会累积误差的动作**。

- 规则：6 次重训 + 2 次校准 → 净 +0.46pp；
- 混合：同样 6 次重训，但多了 3 次校准 → 掉到 −0.84pp；
- 纯模型：2 次重训 + 8 次校准 → −8.07pp。

**重训次数相同时，校准次数越多越差。** 校准是"拿当前 100 条的预测分布去对齐参考分布"，样本太小，估出来的偏差本身噪声很大，一累积就把模型推歪了。

这条和之前合成流上的发现是同一件事的不同侧面：D 组（滑窗重训）恢复段零损失，H 组（只调阈值）恢复段 0.614——**"小声调"不如"大声重来"**。

## 六、这份实验不能证明什么（必须写清）

1. **`retrain` 用了标签**。真实评测里，镜像只能做纯前向，不能训练；这里的重训模拟的是"离线十轮"那一侧，不是在线推理。所以这套对比测的是"离线该选哪个动作"，不是"在线能不能动"。
2. **只有一条流、17 个窗**。A 包只有 1689 条，切完窗每窗 100 条，单窗 F1 波动极大（同一批数据，窗内宏 F1 从 0.16 到 0.64 都出现过，因为窗内只含 1–2 个气体类别）。所以**不要把它当成统计显著的结论**，它只说明"在这个具体设置下，大模型没有优势，而且更差"。
3. **校准的实现是我定的**（logit adjustment）。换成"用累计 300 条估分布"或"只调温度"，结果可能不同。这里没有穷举。
4. **提示词是同一份**（`src/policy.py` 的 `_SYSTEM_PROMPT`），没有为大模型专门设计。如果给它更好的证据描述（比如把"当前窗只含哪些类别"也告诉它），表现可能不一样——但这已经超出"同一个 harness 换决策者"的对比范围了。

## 七、那要不要用大模型

**默认不用，但保留开关。** 理由分三层：

1. **成本**：17 次调用 7,339 token、每次 0.3–0.4 秒；规则是 0 token、0.0 秒。评分表里"资源效率 5 分"按**单位增益消耗的算力/标注配额/大模型 Token** 排名，用 LLM 是纯扣分项。
2. **收益未验证**：唯一一次在官方数据上的对照，结果是更差。
3. **合规**：校选赛阶段拿不到 PyTRiO 额度（`out2.txt:106`），真要在评测里调大模型，得等企业赛。

所以 `--policy rule` 是默认，`--policy llm` / `hybrid` 保留——如果赛道明确要求"Harness 必须由大模型驱动"，改一个参数就能切换，不用重写。

**这件事真正该讲给评审的，不是"我们不用大模型"，而是"我们在官方数据上试过，它更差，所以不用"。** 这比空口说"经过评估"要硬。
