## 一、送分题，但答错会掉档

### Q1 你们做了什么？一句话。

**做了一个"判断该不该动"的系统**，然后在三个官方任务上证明：**大部分时候答案是"不该动"**。

A 包十轮里八轮该回退，B 包六轮全该回退，C 包十轮里四次该回退。评估门拦下的那些动作如果全部执行，三个包的总分会比"什么都不做"更低。

### Q2 为什么不用大模型？

三个理由，按重要性：

1. **合规层**：赛题给了三个选项（直接用 Qwen / 在 Qwen 或 4B 基础上后训练 / 不使用大模型持续训练小模型）。我们走第三项，是官方允许的路径。
2. **物理层**：评测机 8 GB 内存、无 GPU、断网。我们的线性/小 MLP 模型 4326 个参数，前向 0.1 ms；换成 27B 光是加载就要几十秒。
3. **可验证层**：校赛阶段没有 PyTRiO 额度（`out2.txt:106` 写明仅企业赛提供），调不到就无法验证，写进报告也是空话。

**注意别说过头**：不要讲"大模型没用"。我们是"在这道题的成本结构下，它不划算"。

### Q3 和官方基线比，你们好多少？

| 任务 | 基线 | 我们 | 变化 |
|---|---|---|---|
| A 六类气体（Macro-F1 ↑） | 0.7140 | **0.7210** | +0.7pp（**在噪声带内**） |
| B 轴承 RUL（RMSE ↓） | 681.16 | **681.16** | 0（续训全负，交父检查点原样） |
| C 发动机 RUL（RMSE ↓） | 52.87 | **50.93** | −3.66% |

**关于 A 包这个 +0.7pp，要先自己拆掉它**：n=1244、F1≈0.72 时 bootstrap 标准误约 ±1.3pp，**+0.7pp 不显著，我们不说"提升"，说"与基线无显著差异"**。真正站得住的是负向证据：同样八轮动作里，加学习率 −6.43pp、减 batch −4.11pp、多训 20 轮 −0.70pp。**"多动会坏"有证据，"少动能好"没证据**——这个区分必须主动讲，否则被评委问一句"你这个 0.7 显著吗"就崩了。

**B 包要分两层说：训练我们确实一个字没改，但交付的不是官方权重本身。**

先说训练：六个动作全负（最小 +3.6、最大 +33.8 的 RMSE 增量），所以保持官方权重不动。B 包训练集与验证集同分布，续训只会过拟合训练集。

再说交付：十轮全是 `noop`，候选就是平台给的父检查点原样，`steps/epochs` 都是 15/825，没有任何手工改动。所以试运行隐藏流那个 **720.07 是官方模型自身的分布外表现，不是我们改坏的**。

**为什么最终没交收缩版**：v3 提交被平台判不合规，原话是「请基于官方 baseline 及平台提供的父检查点实现真实续训，不要从头训练其他模型」。收缩是手工改权重、`steps` 不变，不满足"候选必须来自续训"。我们撤回，B 与基线同分。收缩实验的数据（α=0.5 时 534.08、逐根 442/543/540、留一验证否定"学 α"）仍在文档里，作为"评估过但没采用"的记录。

**这不是漂移对抗**：没有监测、没有触发、对数据变化无反应。它是"识别出这个包不该动"之后的模型选择。B 包的问题从头到尾不是漂移，是跨个体泛化（训练 9 根、验证 3 根、重叠为零）——给 B 设计漂移检测从第一步就错位了。

## 二、技术追问

### Q4 你们的"漂移检测"具体看什么？

两条无标签信号：**输入分布 PSI** 和**输出分布 PSI**。

关键设计：输出 PSI **用冻结基线的打分算，不用当前模型**。因为模型被漂移带偏之后，坏预测会把输出 PSI 顶高，监测器就一直报警、永远判不出"漂移结束"。这条我们踩过坑——早期版本就是因为这个，D 段（恢复段）一直报警，回滚触发不了。

### Q5 为什么用 PSI 不用别的？

PSI 分箱后算的是边缘分布差，好处是**不看标签、可实时**、阈值有工业界经验值（0.1 提示、0.25 警报）。

**但我们在 A 包上发现了它的量级问题**：128 个特征里有 118 个 PSI 超过 0.25，最大值 2.02，而我们的阈值是 0.10/0.25——差一个数量级，等于没有阈值。这是真数据与合成数据的差别，我们如实写进文档。

### Q6 怎么区分"数据变了"和"规律变了"？

**这是这道题最难的一点，我们只解决了一半。**

- 输入 PSI 高 + 输出 PSI 高 → 大概率是规律变了（该重训）
- 输入 PSI 高 + 输出 PSI 低 → 输入变了但模型还稳（可能只需校准）
- 两者都低但指标掉 → **纯概念漂移，无标签时不可观测**

第三条是数学事实，不是我们没做：输入分布不变、模型不变，输出分布必然不变，任何无标签信号都看不见它。我们实测过——纯概念漂移流上 `pred_psi` 全程 ≤ 0.033、`pred_level` 恒为 0。

**能看见它的只有延迟标签到达后的 AUC/F1。** 所以我们把 AUC 作为第三条信号接了进来（`--third-signal auc`）：AUC 掉了说明排序坏了（该重训），AUC 没掉说明只是阈值偏了（该校准）。

### Q7 那 AUC 这条信号有效吗？

**部分有效，有一个明确的失效场景。**

在 C-MAPSS FD002（六个工况切换）上：+3.14pp，重训次数 6→0，CPU 2.44s→0.00s。

但在我们自己的合成流 B 段上掉 0.26pp：B 段 AUC 0.9996（四段最高）但正例率从 8.2% 涨到 14.2%，AUC 判"不用动"，于是校准钉在旧比例上。

**AUC 只回答"排序坏没坏"，回答不了"是不是标签漂移"。** 我们试过用预测正例率偏差做判据，但和协变量漂移同源（都是输出分布整体偏），一个阈值切不开，已否掉。

### Q8 三个动作分别是什么？几何上什么意思？

- **重训**：把决策边界重新拟合一次（换形状）
- **校准**：只动阈值（平移边界，不动形状），幅度限 ±0.25
- **回滚**：换回旧权重（撤销）

**校准是最便宜的一个，也是最安全的**，因为它错了可以立刻改回来；重训错了不可逆。

### Q9 TTA 你们试过吗？

**试过三条，全负。** 这是我们认为最有价值的一组负面结论：

| 做法 | 平均窗 F1 | AP |
|---|---|---|
| 冻结不动 | 0.6776 | 0.7801 |
| 动权重（熵最小化 + 正例率锚定） | 0.6884（+1.08pp） | **0.7799（不动）** |
| 只换输入标准化统计量 | 0.6468（**−3.1pp**） | 0.7768 |

**第一行加号是假的**：F1 涨了但 AP 一动不动，说明涨的是"阈值碰巧对齐"，排序能力没变。第二行更差，因为它把"特征整体平移"这个真实的漂移信号当噪声抹掉了——而那正是 PSI 要检测的东西。

**唯一有效的是只动阈值，那正是我们的校准动作。**

**注意措辞**：不要说"TTA 无效"，只能说"在我们这条流上、这三种做法无效，且我们没有能公平检验它的纯协变量漂移数据"。严格纯协变量漂移在合成时几乎造不出来。

### Q10 你们的评估门怎么工作？

新模型在验证集上的指标必须优于旧模型才接受，否则回退。

**它救过我们很多次**：A 包十轮里拦下八轮，其中 `lr_hi` 一次就掉 6.43pp。C 包十轮里拦下四轮。

**但它有一个已知失效**：在"连续崩"的场景下它比的是上一窗，上一窗同样错，所以每次都放行。我们实测过——某条流上 11 次重训全被接受，整体 F1 掉到 0.1196。**评估门只能防单次退步，防不住趋势性恶化。**

## 三、会被追问到底的问题

### Q11 A 包只涨 0.7 个点，是不是基本没做出来？

**先承认数字**：+0.7pp 落在噪声带内（bootstrap 标准误 ±1.3pp），我们不把它当成绩。

**正面回答分两层。** 第一层，A 包的 0.7140 里有一个类（Acetaldehyde）的召回本来就是 0，我们查清了原因并证明了它在合规前提下无解——这比刷 0.7 个点有价值。第二层更重要：**我们证明了"能涨分的那些动作，方向和风险都是可测的"**，而结果指向"别动"。

数据：
- Acetaldehyde 在验证集上 109 条里 **108 条被判成 Ethanol**，平均置信度 **0.958**——模型不是犹豫，是"自信地错"
- 在 batch1 上训一个 Acetaldehyde vs Ethanol 的二分类器，拿到 batch2 上：**跨批次 AUC = 0.1137**（分反了，取负是 0.886）
- 而在 batch2 **内部**做五折交叉验证：**AUC = 0.9939**

**同一份特征、同一批类别，在两个批次里相对位置互换了。** 加偏置是平移、重加权是改梯度幅度、过采样是复制样本——**都换不了方向**。

六种救法全试过、全无效：类别加权（权重给到 2.47）、过采样到每类 90、修正官方 shuffle、加偏置、输入归一化、组合。

**要救只能拿 batch2 重新对齐坐标系，而 `TRAINING_GUIDE.md:32` 明令禁止验证集参与拟合任何统计量。** 我们选择守住规则、接受它。

### Q12 那你们怎么不去争更多的分？

**我们盘过账**：A 包剩余可优化空间合计不到 3pp。逐类拆开：Ethanol 0.6885（精确率被 108 条错判永久压低）、Toluene 0.7143（验证集只有 5 条，一颗样本跳 0.2）、Ethylene 0.9485、Ammonia 0.9804、Acetone 0.9972。

**Toluene 只有 5 条样本这一条，就意味着这个数不可优化**——不是算法问题，是统计问题。

如果追问"那你们做了什么"，答：**我们把力气花在"不该动的别动"上**，因为那是唯一有确定收益的方向（B 包不动 = 保住基线，动了全掉）。

### Q13 "越用越会调"你们证明了吗？

**没有，如实说。**

评分表这一项要的是"同一类漂移反复出现时，恢复所需轮数递减"。我们只有一条连续迭代链（A 包 10 轮），凑不出重复事件。

我们做到的是"**在合适时机停手**"——A 包八轮六次回退，B 包六轮全回退。这是"收敛"，不是"进化"。

**不要试图包装它。** 答辩时主动说"这一项我们拿不到分，原因是缺重复事件而不是缺方法"，比被问出来的效果好。

### Q14 归一化增益 G 是多少？

**算不出来，我们不自造公式。**

G 的定义是 `(我们的 − 基线) / (全量重训 − 基线)`。分子我们有，**分母要求"全量重训这个天花板能好多少"，而官方没有定义"阶段"是什么**。

我们改报绝对增益（+0.98% / 0 / −3.66%）和单位成本增益，并在报告里写明分母未知。**自造一个 G 出来，一旦官方口径不同，整个报告的数字全废。**

## 四、工程问题

### Q15 镜像多大？构建要多久？

**345 MB**（限制 2 GB），`docker build --network none --no-cache` **8.8 秒**。

离线构建靠的是把 numpy wheel 放进 `vendor/wheels/`，`pip install --no-index --find-links`。**不联网也能构建，这一点我们实测过**——因为这个错过一次：仓库最初推上去时漏了那个 17.4 MB 的 wheel，`COPY vendor/wheels/` 会直接失败，评审克隆下来根本构建不出来。

### Q16 三包跑完要多久？

**约 3 秒**（A 1244 行 / B 1679 行 / C 23049 行）。评测墙钟预算 6 小时，前向不是瓶颈，瓶颈在容器启动和镜像拉取。

**冷启动 300 ms** 是 `import numpy` + 加载三个 checkpoint，不是计算。

### Q17 输入输出格式怎么保证兼容？

我们没重写 `baselines/predict.py`，只写了薄薄一层 `harness/predict.py`，输出格式与官方**逐字节相同**（分类 `{"outputs":[{"label","score"}...]}`、回归 `{"outputs":{"value":x}}`、逐行 flush）。

三包全量对比过，A/B/C 输出与官方 adapter 完全一致。

**新协议（SDK 1.0.2）多一条硬校验**：请求必须同时带 `task` 和 `inputs`，`contest_harness/predict.py:98` 缺 `task` 直接 `PREDICTION_REQUEST_INVALID`，而且这层没有 try/except 包住——**一行不合法，整进程 exit 1，后面的行全丢**。

问："你们怎么保证平台喂进来的格式一定对？"
> 不保证。这是 SDK 层的硬校验，平台按契约喂就不会触发；我们能控制的是拿到 `Sample` 之后任何异常都不让进程死（`predict()` 整体 try/except → 兜底输出）。**契约层的失败是接口不匹配，不是我们的实现缺陷**——这两件事不能混着说。

### Q18 有没有做过容错？

**两个会毁掉整份评测的 bug，我们自己找出来修了**：

1. **UTF-8 BOM**：Windows 导出的文件常在开头带一个 `\ufeff`，它不是空白字符、`.strip()` 删不掉，`json.loads` 抛 `Unexpected UTF-8 BOM`。BOM 只在文件开头出现一次 → **受影响的是首行** → 首行落入兜底分支、输出六类各 1/6 的均匀分数。修复：`json.loads` 之前 `lstrip("\ufeff")`。实测 A 包全量 1244 行，带 BOM 与不带 BOM 都是 **macro-F1 0.7210，逐位相同**。
2. **坏行杀进程**：任何一行解析失败会让整个进程 `exit 1`，后面所有正常行全丢。改成单行失败记 stderr + 输出兜底答案，保证输入行数 = 输出行数。

这两条都不会让分数变高，但前者会让首行静默变成一次随机猜，后者会让整份输出截断——两种都是"跑完了、看起来成功了、结果是错的"，比直接崩溃更难发现。

## 五、最容易被问倒的一题

### Q19 你们的核心结论是什么？如果只留一句话。

> **训练数据与评测数据同分布（同批次）时，把损失函数从交叉熵换成 focal，Acetaldehyde 从 0.00 到 0.96、总分 0.6880→0.8871；两者跨批次时，同样的替换反而更差（0.7226→0.7133）。官方评测只给我们旧批次（batch1）的标签、隐藏流是新批次，属于后者——所以在可用的条件下，多动不如少动。**

这个边界钉在**数据分布**上，不是"我们的方法更好或更差"，也不是"有没有新批次标签"（拿到 batch2 标签去训、再拿 batch3 测，仍然是跨批，focal 未必反转——这一点必须自己先讲，否则被问一句就破）。它一次解释三组数字：跨批调参无效（+0.7pp 在噪声带内）、同批 focal 有效（0.8871）、官方口径 focal 更差（0.7226→0.7133）。

**两个数不能并排比**：同批那个 0.8871 的测试集是 batch2 内部的 374 条（870 训 / 374 测），官方口径那个 0.7133 的测试集是整个 batch2 的 1244 条。分母不同，只能作为"方向性对照"引用，不能说"差 17.4 个百分点"。

**这里必须主动分层，否则会被读成"你们的价值就是学会不做事"：**

- **训练层**：我们没有能力差异可讲——跨批次两种损失函数一样烂，所以这一层只做无损或少损的保守动作。这是"约束下的最优"，不是优点。
- **决策层**：这才是真本事。同一个证据包，规则 0.7256、27B 0.6403，**−8.1pp 远超噪声带**。差在哪？27B 更保守，把本该重训的 6 次改判成校准，而校准在 A 包上负收益。

> **我们不是在"不动"这件事上比谁聪明，是在"该不该动"这件事上比 27B 判断得准——而这恰恰是十轮迭代里唯一能产生分差的自由度。**

**但请注意这句话只在校赛条件下成立，企业赛条件下会反转——这一点我们主动说，因为不说也会被问出来。**

我们按企业赛的真实形态补做了滚动留一批实验（只用已到手批次训练、在下一批未见数据上测，八轮）：冻结 0.386 → **每轮无条件续训 0.705（+31.9pp）**。然后把评估门加进去，结论反过来：

| 策略 | 八轮均值 |
|---|---|
| 每轮都接受 | **0.7050** |
| 有门（用固定 batch2 判） | 0.5743 |
| 有门（用全历史均值判） | 0.3726（第 2 轮就锁死） |

原因：**新模型在旧批次上先升后降，在新批次上单调上升，两件事不同步。** 第 7 版在 b9 上 0.987、在 b3 上只比第 3 版高 0.003，但门看的是"旧课有没有掉分"，第 4 版掉 0.005 就被退回，白丢后面所有收益。

所以我们的完整答案是两层：**没有新数据时靠纪律（校赛：多动不如少动）；有新数据时靠数据（企业赛：每轮都训，别让门拦着）。** 这也顺带解释了"抗遗忘 5 分"与"适应漂移"是同一矛盾的两面——任何真适应都会让某些旧批次掉分。

证据：
- A 包：不动 0.704，动 100 条 0.520，动 300 条 0.340，动 800 条 **0.166**
- B 包：训练六个动作全负（681.16 未动），交付父检查点原样（收缩实验做过，因不合规未提交）
- C 包：十轮里只有六次接受，后三轮回退

**机制解释**：A 包极度不平衡（一类占 42.8%、另一类 0.4%），模型越训越倾向全判多数类——准确率飙到 99.6%，宏 F1 跌到 0.166。**这是"用错误的目标优化"的典型，不是"模型不行"。**

### Q20 如果多给两周，你们会做什么？

按优先级：

1. **试运行演练**（现在还没跑过，平台有个"15 秒自动停止"的已知 bug，必须提前踩）
2. **A 包用 train 内部切验证集做干净的选择**（公开 val 只用来报告，不用来搜索）
3. **补重复事件**——如果能构造出"同类漂移反复出现"的多条流，"越用越会调"这一项才有证据
4. **C 包改结构**——但改结构会切断 `parent_checkpoint_sha256` 的父子链，代价高于收益，所以现在没做

## 附：如果被问"长尾 / Long Tail 你们怎么处理"

**一句话**：是典型长尾，但比标准长尾更麻烦——**不只是尾部样本少，是尾部的位置会变**。

先把两批的分布摆出来（全篇最能说明问题的一张表）：

| 批次 | 最多 | 最少 | 相差 |
|---|---|---|---|
| batch1（训练，445 条） | Ethylene 98 | **Acetaldehyde 30** | 3.3 倍 |
| batch2（验证，1244 条） | **Acetone 532（42.8%）** | **Toluene 5（0.4%）** | **106 倍** |

batch1 里 Toluene 有 74 条（16.6%），batch2 里只剩 5 条；batch1 里 Acetaldehyde 30 条，batch2 里 109 条。**这一批的尾巴和下一批的尾巴不是同一根。**

**标准解法我们全试过，而且先在"同分布"下试**（batch2 自己切 70/30，870 训 / 374 测）：

| 方法 | 宏 F1 | Acetaldehyde 召回 |
|---|---|---|
| 普通交叉熵 | 0.6880 | 0.00 |
| **Focal Loss（γ=1）** | **0.8871** | **0.96** |
| 类别加权 1/√freq | 0.8856 | 0.94 |
| 过采样 5× / 10× | 0.8813 / 0.7630 | 0.93 / 0.82 |

⇒ **长尾解法在同分布下非常有效，+19.9pp。**

**但换成真实口径（batch1 训、batch2 测），全部失效**：

| 方法 | 宏 F1 | Acetaldehyde 召回 |
|---|---|---|
| 冻结 | **0.7210** | 0.00 |
| 普通 CE | 0.7226 | 0.00 |
| Focal γ=1 / γ=3 | 0.7133 / 0.6919 | 0.00 / 0.00 |

**为什么**：跨批次 Acetaldehyde vs Ethanol 二分类 AUC 是 **0.1137**（分反了，取负才 0.886），而同批次内部 5 折 AUC 是 **0.9939**。两团在新批次里互换了位置，任何损失函数都换不了方向。

**所以结论是"要数据不要损失函数"**：官方第二批数据一到，Acetaldehyde 从 30 条变 240 条，召回从 0 到 0.99，宏 F1 从 0.714 到 0.919。这也是我们主张"每轮用全部历史重训"的根本原因。

**顺手解释赛题为什么用 Macro-F1**：如果用准确率，把只占 0.4% 的 Toluene 全判错几乎看不出来；用宏 F1，它那一类的 F1 直接是 0，六类平均掉 0.167。**这个指标就是专门用来惩罚"忽视尾部"的**，选它说明出题人知道长尾是这题的真难点。

## Q21. 第 9、10 轮的动作名和前面不一样，是不是为了凑轮数补的？

不是。前 8 轮把动作空间试完了——学习率三档（0.0015 / 0.003 / 0.006）、batch 两档（64 / 256）、续训轮数两档（10 / 20）；第 9 轮时程序输出 `动作空间耗尽` 并主动停止。

补的两个动作（`lr=0.002`、`epochs=40`）是对已有动作边界的收尾：lr 从 0.0015 / 0.003 / 0.006 补一个中间值，epochs 从 10 / 20 补一个更长的。**两轮都被拒，最佳仍是第 3 轮的 0.7210。**

所以准确说法是：**动作空间是被穷尽后自然停止的，不是预算用完。** 十个方向试下来没有一个超过第 3 轮，这本身就是“多动不如少动”的第十条证据。

## Q22. 你们的策略在 A 包上只有 0.71618，比固定动作表的 0.72099 还低——那这套策略是不是没用？

**比固定表低 0.48pp 是真的，脚本可复现（`tools/exp_policy_rounds.py`）。** 这个数我们没藏，写在 `docs/省轮次对照.md` §5.1 和作品文档第六节第 10 条。

**但低的原因不在"策略"这一层，在 R1 判据太严：**

回放里 `retrain_20` 试了三次，Δ 分别是 +0.00215 / −0.00702 / −0.00702。后两次失败只有 **−0.70pp，落在 ±1.27pp 噪声带内**，而 R1 的判死条件是"连续两次**超带**退步"——它永远够不上，于是凭"规则建议优先"一直占着候选第一位，`lr_lo`（固定表第二个涨分动作）一次都没轮到。

**补上 lr 维度也救不了**：S2 把 `lr_lo` 加进动作集，结果与 S1 **完全相同**（0.71618）。因为问题出在"谁排第一"，不是"有哪些可选"。

**为什么赛前不修**：改判据（"连续 2 次带内且为负 ⇒ 换方向"）要重跑回放、改文档、重打镜像，而能拿到的上限是 0.7230（+0.2pp），在 ±1.27pp 噪声内。**同一个标准：既然 +0.48pp 判不显著，+0.2pp 就不值得动已冻结的镜像。**

**那这套策略的价值是什么**——三条，都不靠分数：

1. **它说出了"为什么停"。** 固定表是"动作试完了自然停"，策略是"连续三次带内 ⇒ 判定平台期 ⇒ 停"。后者是可解释的判据，前者是穷举自然的尽头。
2. **它省了 4 轮**（第 5 轮进 `noop`，固定表第 5–10 轮还在试），而那 6 轮**真的训出了更差的模型**（0.7143 / 0.6861 / 0.6697），只是被门拦下没上线。
3. **它的失败是可诊断的。** 被问到"为什么低 0.48pp"，我们能指到具体一行判据；固定表如果低，只能答"试完了没有更好的"。

**一句话答完**：这套策略不是"能自动找到更好的动作"，是"**能在噪声里识别出'再试也没用'**"——而在 A 包这个数据上，它连这件事都做得不够好。这个结论是量出来的，不是推的。

## Q23：B 包不动，是不是因为 `label_provenance` 卡住了你们？

**不是。这条要主动澄清，否则会被当成掩饰。**

`baselines/train.py:52-60` 的校验是：

```python
if label_provenance is None:
    raise ValueError("B requires explicit label provenance; do not silently derive official health labels from RUL")
if declared["status"] not in ("draft", "approved") or not method:
    raise
```

关键在 `:145` 的 help 原文：**"declared approval is not verified here"**——它只要求**声明**，不验证批准。官方自己的测试用例 `tests/test_baselines.py:136` 用的就是 `{'status':'draft','method':'test fixture labels; not committee approval'}`，明确写着"不是委员会批准"也能跑通。

**我们也实测了**：带一个 `{"status":"draft","method":"健康标签由 RUL 阈值派生，自行声明，未经委员会批准"}` 的 JSON，B 包回归训练正常产出 checkpoint，3 epoch 验证 RMSE 从 953.10 降到 **590.93**。

**所以"B 不能训"是错的，我们不训是因为训了更差：**

| 方向 | 验证 RMSE | 对比官方 681.16 |
|---|---|---|
| lr 0.0015 | 689.16 | +8.00 |
| lr 0.006 | 684.75 | +3.59 |
| bs 64 | 689.60 | +8.44 |
| bs 256 | 714.93 | +33.77 |
| epochs 10 | 702.74 | +21.58 |
| epochs 20 | 708.32 | +27.16 |

六次全部从同一个官方 checkpoint 出发、各改一个参数，**没有一次让 RMSE 变小**。

**更深一层的原因是官方那个 checkpoint 本身就停在最差的一轮。** 从 `history.jsonl` 读出来，15 个 epoch 的验证 RMSE 是 580.15 → **567.15（第 2 轮最好）** → 590.93 → 645.42（第 10 轮）→ **681.16（第 15 轮，官方公布值）**，训练 loss 从 0.674 单调降到 0.10。**它已经明显过拟合，从它续训只会更过拟合。**

**为什么不干脆从头训**：3 epoch 就能到 590.93，比 681.16 好 90。但 `parent_checkpoint_sha256 = null`，平台公告禁止"从头训练冒充续训"，这个产物**物理上不可提交**。

**一句话答完**：`label_provenance` 不是墙，是一道需要签字的门；门后是更差的结果。我们签得起，但没必要。

## Q24：C 包的误差主要集中在哪种数据上？

**集中在 FD004——多工况叠加多故障模式。分 FD 看，数字是清楚的。**

C 包的 `public/validation.jsonl`（23,049 行）是 C-MAPSS 四个子集验证集的合并，行数逐一对得上（3,210 + 7,581 + 3,555 + 8,703 = 23,049；训练集 14,130 + 38,034 + 17,529 + 43,396 = 113,089）。**这不是新数据，是同一份数据的另一种切法**，不碰隐藏流。

用当前提交权重（十轮链 r07）分 FD 评估：

| 子集 | 工况 | 故障 | n | RMSE | 平均偏差 | NASA |
|---|---|---|---|---|---|---|
| FD001 | 1 | 1 | 3,210 | **39.39** | +4.16 | 1.3e6 |
| FD002 | 6 | 1 | 7,581 | **40.53** | +8.77 | 7.7e6 |
| FD003 | 1 | 2 | 3,555 | **50.92** | +13.90 | 3.6e8 |
| FD004 | 6 | 2 | 8,703 | **61.71** | **−7.56** | 2.7e9 |
| 全量 | | | 23,049 | 50.93 | | 3.0e9 |

**三个结论：**

1. **短板在 FD004，不在"整体"。** FD001/FD002 已经做到 39–41，真正拖后腿的是 FD004——6 种工况 + 2 种故障模式叠加，本质上就是协变量漂移与概念漂移同时发生。
2. **NASA 分数的 99.7% 来自 FD003 + FD004**（9.0e6 对 3.03e9）。极端样本集中在最复杂的两个子集，这是指标指数放大的性质，不是模型在某处"崩了"。
3. **偏差方向在 FD004 反转**：前三个都高估（+4.2 / +8.8 / +13.9），FD004 是低估 **−7.56**。这直接说明**全局常数修正在数学上不可行**——任何单向偏移都会让一半子集变好、另一半变坏。

**不能说的一句**：不能声称"FD004 上也能做到 39"（没试过），也不能算"分 FD 后相对冻结基线提升多少"（冻结基线没分 FD 算过）。

**更不能用它调参**——这张表只用于定位问题。照着它去改模型，就是拿验证集调参。

## Q25：你们试过改网络容量吗？为什么不加宽/加层？

**查清楚了，不是"没想到"，是"改了也接不上"。**

官方 `baselines/model.py` 把结构写死成一层 tanh 隐层，`Model.load` 只认 `w1/b1/w2/b2/mean/scale/metadata` 七个键。`train.py:75` 有这句：

```python
if resume and config["hidden"] != model.meta["hidden"]:
    raise ValueError("resume hidden width must match checkpoint; changing the profile does not migrate weights")
```

**它只在 `--resume` 时拦。** 所以官方口径是"允许改结构，但必须自己迁移权重"：新结构里旧通道原样放入、新通道填 0，`mean/scale/target_*` 不动，`parent_checkpoint_sha256` 仍写官方 sha。

**三条硬约束**（`model.py:57`、平台公告）：参数总量 < 100,000、`hidden` ≤ 128、checkpoint ≤ 16 MiB。

**我们没做的三个理由：**

1. **成本一天起**：权重迁移半天 + 重跑十轮 2–3 小时 + 三包验证重打镜像半天 + 新提交与一次试运行 4 小时。距截止 4 天。
2. **没有证据说加宽有用**。我们唯一的架构对照是参考方案（128 宽三层），它在 A 包上 **0.7345**（+1.35pp），且是从零训练、`parent=null` 不可提交。C 包输入只有 24 维、每轮 11 万行，加宽大概率被过拟合吃掉。
3. **风险不对称**：改坏了要回滚，而 `sdk6` 是已完整跑通十轮的那一版。

**唯一试过的方向**：让队友在 C 包上扫宽度（32 对照 / 64 / 128，同数据同 lr 同 40 epoch），判据是"**只有比 32 低 0.5 以上才值得继续**"。结果见 `docs\给队友_改结构说明.md`。

**不能说的一句**：不能说"加宽会更好"或"加宽没用"——**我们没在合规路径上试过**，只能说"判断不值得在剩余时间内承担这个风险"。
