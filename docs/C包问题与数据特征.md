# C 包问题描述与数据/模型特征

> 数据来自官方包 `data/official/cpu-c-guide-20261110-v1`（2026-11-10 版，sha256 `6CB8784E…E4211F`），
> 所有数字均可在本机复现。指标口径：RMSE、MAE、NASA 评分（PHM08 分段指数惩罚，欠预测罚得更重）。

## 一、问题定义

**任务**：C-MAPSS 涡扇发动机剩余寿命（RUL）回归。输入一条"单周期快照"（当前周期的 3 个工况设定 + 21 个传感器读数），
输出该发动机**距离失效还剩多少个周期**（0–434+，单位：周期）。

**评测**：离线批量推理，隐藏集 9,687 行（公开验证集 23,049 行的 42%），
十个更新轮次、每轮换取新一批数据并允许续训，最终取最好的一轮产物。

**归一化增益**（平台口径）：`G = (我们的指标 − 静态基线指标) / (参考上界 − 静态基线指标)`，
参考上界 = 组委会"每阶段全量标签重训"的结果。

## 二、观察到的核心现象

### 2.1 三个差别很大的模型，隐藏流上几乎一样

| C 的产物 | 公开验证集 RMSE | 隐藏流 RMSE | 隐藏流 NASA |
|---|---|---|---|
| 官方冻结权重（起点） | 52.8686 | **55.8126** | 8.1113e10 |
| 镜像内冻结权重（我们交付的） | 50.9320 | **55.8126** | 8.1113e10 |
| `c_long` 900 轮 + 寿命单调正则 | 50.2190 | **55.8126** | 8.1113e10 |
| 官方路径 `retrain_300` | 50.4484 | **55.7955** | 1.3332e11 |

- 公开集从 52.87 压到 50.07（−5.3%），**隐藏流一位不差**（55.8126 出现三次，第 13 位小数都相同）。
- 唯一动了隐藏流的（55.7955）是官方训练器产物，但 NASA 反而从 8.11e10 恶化到 1.33e11（+64%）。
- 结论：**公开集上的提升完全不过去**，且隐藏流的分数对 C 的模型改动极不敏感。

### 2.2 公开集的四个子集，短板集中在 FD003/FD004

| 子集 | 官方冻结 | 我们（`c_long`+正则） | 行数占比 |
|---|---|---|---|
| FD001 | 42.83 | 39.37 | 14% |
| FD002 | 41.15 | 39.58 | 33% |
| FD003 | 55.36 | 48.58 | 15% |
| FD004 | 63.24 | 61.16 | **38%** |

FD004 占 38% 的行、RMSE 61，是唯一的大短板；FD001/FD002 已经接近该数据的噪声底。

### 2.3 L2 收缩（B 包那招）在 C 上会塌

| 配置（MSE，lr 0.002，300 轮） | 公开集 RMSE |
|---|---|
| wd = 0.0 | 50.6455 |
| wd = 0.5 | 79.5796（塌成常数） |
| wd = 1.0 | 79.5629（塌成常数） |
| wd = 2.0 | 79.5255（塌成常数） |

原因：B 的验证集 90% 是长寿命轴承，常数预测就能赢；C 的标签 0–434、四个子集分布不同，一压就全体塌。

## 三、公开验证集的特征

### 3.1 规模与构成

| 子集 | 验证行数 | 发动机数 | 工况 | 故障模式 | 标签 min/max | 均值 | 标准差 | 中位数 |
|---|---|---|---|---|---|---|---|---|
| FD001 | 3,210 | 15 | 1 种 | 1 种 | 0 / 292 | 109.3 | 66.6 | 106.5 |
| FD002 | 7,581 | 39 | **6 种** | 1 种 | 0 / 268 | 99.6 | 61.0 | 97 |
| FD003 | 3,555 | 15 | 1 种 | **2 种** | 0 / 408 | 128.1 | 86.0 | 118 |
| FD004 | 8,703 | 37 | **6 种** | **2 种** | 0 / 434 | 130.8 | 90.8 | 117 |
| 合计 | 23,049 | 106 | — | — | 0 / 434 | — | — | — |

训练集对照：113,089 行 / 496 台发动机（FD001 70、FD002 182、FD003 70、FD004 174）。

### 3.2 三个关键结构事实

1. **验证集与训练集没有一台发动机重叠**（逐子集核对：overlap = 0）。所以验证集本身是"没见过的机器"，
   但仍然是**同一批数据源、同一种采集条件**下的没见过的机器。
2. **每个样本只有 1 个周期**（`meta.window_size = 1`，全部 23,049 行都是），输入里**没有任何时序信息**——
   同一台发动机前后两个周期的预测之间没有任何结构性约束，模型只能看到"当前这一帧"。
3. **标签上限不截断**：标准 C-MAPSS 惯例把 RUL 截到 125/130，这个包没有（最大 434，训练集最大 542），
   所以晚期样本的标签很大，绝对误差也大，NASA 评分对大误差是指数惩罚。

### 3.3 输入维度

`inputs.settings` 3 维（工况：高度/马赫/油门）+ `inputs.sensors` 21 维 = **24 维**，无缺失。

## 四、官方模型的特征

| 项 | 值 |
|---|---|
| 结构 | 24 → 32（tanh）→ 1，**833 个参数** |
| 损失 | MSE（对 `(y − target_mean)/target_scale` 归一化后的标签） |
| 优化器 | Adam（β 0.9/0.999，eps 1e-8），梯度裁剪 5.0 |
| 超参 | lr **0.006**、batch **256**、**15 个 epoch**、seed 42 |
| 步数 | 55250（= 15 × 442，442 = ⌈113089/256⌉） |
| 发布版本 | 15 轮里**最靠后的那版**（ep15），公开集 RMSE 52.8686 |
| 逐轮曲线 | ep1 56.59 → ep2 53.31 → ep3 52.60 → … → **ep14 51.85（最好）** → ep15 52.87 |

三点解读：

1. 这是**很弱的模型**（833 参数 / 113,089 样本 ≈ 1:136），容量小到几乎不可能记住训练集，
   所以它的问题不是过拟合训练集，而是**欠拟合 + 系统性偏差**。
2. 官方发布的不是最好那轮（ep14 51.85），说明他们按"最后一轮"发版，随手就能白拿 1 个点。
3. 参数/样本比与 B 包形成鲜明对比：B 是 865 参数 / 7,032 样本（1:8，严重过拟合），
   C 是 1:136（严重欠拟合）。**同样一句"续训"，对 B 有害、对 C 有益**。

## 五、为什么这件事难（问题本质）

1. **单帧输入、无时序**：模型看到的是一个瞬间的传感器读数，不是退化轨迹。
   同样一帧读数可能来自"刚装上"和"快坏了"两台机器（工况与个体差异淹没了退化信号）。
2. **个体差异 > 退化信号**：验证集 106 台发动机、寿命跨度 0–434，
   我们最好的模型误差 ≈ 50 个周期，而发动机之间寿命差异本身就有 ±90（标签标准差）。
   **误差的主要来源是"这台机器天生能用多久"，不是"现在退化到哪一步"**，而前者在输入里没有信息。
3. **公开集同源、隐藏集不同源**：公开验证集和训练集来自同一采集批次（同 4 个子集、同样工况划分）、
   只是发动机不同；隐藏集是另一批评估数据。公开集上学到的"这批机器的偏差校正"到隐藏集就失效了。
4. **没有同流基线**：官方从不公布隐藏流的基线分数，我们只能从 diag 运行反推出基线用的就是官方权重
   （55.8126 / 8.1113e10），归一化增益的分母也是未知的，导致 −0.34 这种"看起来在退步"的读数无法解释成绝对好坏。

## 六、可尝试的方向（按性价比排序，均需在合规约束内）

1. **少训 + 先验**：900 轮在公开集降 5% 但不迁移，是"过拟合公开集"的典型形状；改成 300 轮 + 寿命单调正则
   （同一发动机相邻周期预测不得随周期增大），公开集约 50.3–50.5，但更"钝"，可能更迁移。→ 一次试运行可验证。
2. **把轨迹信息显式喂进去**：合规前提下只能改训练目标（不能改模型输入结构，否则无法从父检查点续训），
   所以用"相邻周期配对惩罚"这类软约束近似时序先验（已实现，公开集 NASA −35%）。
3. **按子集/工况自适应**：FD002/FD004 是 6 工况，理论上应做工况归一化；但需要重训第一层、改动大、
   且隐藏集是否同样分工况未知。
4. **接受 C ≈ 0**：C 在 mean_gain 里只占 1/3 权重，且已被截零；把精力放到 A/B 的边际收益更高。

## 七、"生命周期"在线校正：做了，否了（2026-11-28）

**假设**：单帧输入丢掉了"这台机器退化得多快"。如果评测按台连续喂帧（工业现场就是如此），
可以用这台已走过的帧估它的退化斜率，再修正当前预测——这正是"寿命模型/专门算法"的合规嫁接形态。

**三种做法与结果**（公开验证集 23,049 行 / 106 台）：

| 做法 | RMSE | 说明 |
|---|---|---|
| 单帧线性基线 | 53.287 | 参照 |
| ① 斜率外推 RUL=(HI_f−HI_t)/b | **90–104** | 除法放大斜率噪声，灾难 |
| ② 把斜率当特征学修正（线性基线之上） | **52.40**（−0.9） | 有效，但只补到"线性模型"水平 |
| ③ 同上，叠加在 `c_long` 900+单调正则之上 | **50.150**（−0.07，0.14%） | 增量几乎为零 |
| ③ 的尾部/加权指标 | 5.77e11 → 4.47e11（−22%） | 指数型指标上的改善，但样本方差同量级 |

**为什么否**：
1. ③ 的 RMSE 增益只有 0.14%，小于"换一批发动机"的抽样波动（隐藏流三次完全相同也说明这点）；
2. 真正有用的是"知道是哪台"，而在线斜率只能部分恢复它，且要先假定行按台连续——隐藏流排布未知；
3. 合规上，predict 期改动输出会被入口预检的"不要修改模型输出"直接点到；训练期正则（已采用的单调惩罚）才是安全位置。

**复现**：`.team/_c_online.py`（① 与顺序敏感性）、`.team/_c_online2.py`（② 线性基线）、`.team/_c_online3.py`（③ 叠加我们的模型）。

## 八、训练期样本加权（按真值 RUL 分段）

思路来自第 4 节的误差账本：真值 RUL ≥ 200 的健康期样本只占 15%，却贡献 52% 的平方误差，
且那一段的传感器读数已经饱和。于是试"训练时给健康期降权"，看能否把容量集中到退化段。

配置与 `c_long` 完全一致（lr 0.002、900 轮、单调正则 λ=0.5、回滚验证最好轮），**唯一变量是样本权重**：

| 配置 | 权重 | RMSE | MAE | NASA | pred_std | 回滚轮次 |
|---|---|---|---|---|---|---|
| `base`（现行提交） | 全 1 | **50.2190** | 35.6162 | **3.664e9** | 59.87 | 780 |
| `w04` | RUL≥200 取 0.4 | 51.6499 | 36.1424 | 7.909e9 | 53.20 | 801 |
| `w02` | RUL≥200 取 0.2 | 52.8686 | 38.8998 | 5.823e9 | 58.85 | **15**（全程回滚到父权重） |
| `smooth` | 1 − 0.6·clip((RUL−120)/300) | 50.7140 | 35.6001 | 4.383e9 | 56.25 | 853 |

逐子集 RMSE（FD001/FD002/FD003/FD004）：

- `base`：39.08 / 39.36 / 48.43 / **61.71**
- `w04`：39.28 / 38.61 / 48.56 / **65.07**
- `smooth`：39.15 / 38.83 / 48.06 / **63.16**

**结论：降权无效，且随权重加大单调变差。** 权重 0.2 那档更极端——900 轮里没有一轮能超过初始权重，
整个训练被"回滚最好轮"机制作废，等于什么都没学到。

**为什么**：健康期样本贡献的是"**误差**"，但同时也是"**约束**"。降权后模型在健康期失去锚点，
开始过度外推，FD004（工况最多、寿命跨度最大）从 61.71 恶化到 63–65。
"误差集中在某段"不等于"该段可以忽略"——这两件事在 C 上是反的。

**为什么不再往下试**：三条合法路线（分段加权、辅助任务蒸馏、teacher-student）里，
后两条要么改结构（`resume hidden width must match checkpoint`）、要么依赖"从传感器估出是哪台"，
而后者留一 R² = −0.264（第 6 节）。加权这条实测为负。C 的合规改造窗口到此为止。

**复现**：`python .team/_c_weight.py`（四个配置顺序跑，结果落 `.team/c_weight.json`，全程约 16 分钟）。
