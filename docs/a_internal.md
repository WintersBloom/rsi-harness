# A 包：内部验证集不能替代跨批次验证（否定结论）

> 一句话：在 batch1 内部切 20% 选配置，选出来的"最优"在 batch2 上更差。
> 这不是方法没调好，是**这个指标本身量错了东西**。

## 一、动机

公开 `validation.jsonl`（batch2，1244 条）是唯一能反映"跨批次"的样本。但我们只有这一份，
反复拿它试配置就是在对 batch2 过拟合——隐藏测试流是 batch3–10（跨 8 个月，离 batch1 更远），
在 batch2 上挑出来的最优，到隐藏流上大概率不成立。

`TRAINING_GUIDE.md:32` 也明确禁止验证集参与拟合任何统计量。

所以计划是（Planner §10.5）：**用 train 445 条分层切 20%（90 条）做内部验证集选配置，
选定后全量重训，public val 最后只跑一次报数。**

这个计划的隐含假设是：*内部验证集上的好坏，能预测跨批次的好坏。*
本实验就是去验证这个假设——**结论是假设不成立**。

## 二、方法

- `tools/probe_a_internal.py`，固定种子 `20261115`
- 分层切分：不整体切 20%，而是**每类各取 ceil(n_k × 0.2) 条**，保证小类也有代表
  - fit 355 条 / holdout 90 条
  - holdout 按类：`[18, 20, 17, 6, 14, 15]`（Ethanol / Ethylene / Ammonia / Acetaldehyde / Acetone / Toluene）
- 只从官方 `checkpoint.npz` 续训，搜索 12 组（epochs × lr × 是否类别加权）
- 每组：在 355 条上训练，在 90 条上算 macro-F1

## 三、结果

### 3.1 内部验证集上，12 组配置全挤在一个窄带里

| 配置 | internal macro-F1 | Acetaldehyde |
|---|---|---|
| ep10 / ep20 / ep20-lr0.0015 / ep10-lr0.0015 | 0.9475 | 0.800 |
| ep20-lr0.006 / ep40-lr0.0015 / ep20-lr0.0015-cw / ep10-lr0.003-cw | 0.9707 | 0.909 |
| **ep40-lr0.003（最优）** / ep20-cw / ep40-cw / ep40-lr0.0015-cw | **0.9912** | **1.000** |

差距只有 **4.4pp**，且 **ep10 与 ep20 完全一样（0.9475）**——
说明在 batch1 内部，模型几乎瞬间就收敛了，"再训几轮"这件事本身没有区分度。

### 3.2 public val 上，同一批配置全在 0.69–0.72

对照：官方配置 ep20-lr0.003 在 public 上是 **0.7040**（此前多次复现，逐位一致）。

### 3.3 决定性的一步：把内部最优拿到 public 上

```
internal 最优: ep40 lr0.0030 cw=False → 0.9912（相对官方配置 +4.37pp）
全量重训后 public val macro-F1 = 0.6919（官方配置 0.7040，-1.21pp）
per-class: Ethanol 0.645  Ethylene 0.932  Ammonia 0.863
           Acetaldehyde 0.000  Acetone 0.997  Toluene 0.714
```

**内部验证集涨 4.37pp，公开验证集掉 1.21pp。**

## 四、为什么方向是反的

内部验证集和训练集**来自同一个批次同一个月的同一台设备**。
在它上面，"训得更久"等价于"把 batch1 的样本背得更熟"——
Acetaldehyde 内部 F1 从 0.800 涨到 1.000，就是把它那 6 条 holdout 样本记住了。

而跨批次真正需要的，是**别把 batch1 的绝对量级当真理**——
f041 的均值在 batch2 里是 batch1 的 6 倍。训得越久，模型越确信"f041 大约 4.5"，
到 batch2 就错得越狠。

所以内部验证集度量的是**过拟合程度**，不是**泛化能力**。
拿它做"选最优"，等于在选"过拟合得最厉害的那个"。

## 五、这条结论的三个含义

1. **A 包没有合规的调参手段。**
   public val 不能反复用（会过拟合 batch2），internal val 方向反了。
   剩下唯一正当的操作是"基于机制的保守动作"——比如十轮链里唯一有效的 R3 `lr=0.0015`（+0.48pp），
   它涨分不是因为被验证集选中，而是因为**改动更小**。

2. **"多训几轮"在 A 包上是负向动作。**
   这与十轮链的实验一致：8 个动作里 6 个回退，`lr_hi`（0.006）掉 6.43pp 是最惨的一次。

3. **Planner §10.5 的计划需要修正。**
   原计划"用 internal val 选配置、public val 只跑一次"，
   现实是 internal val 无法承担"选"这个职能。它只能用来**做健全性检查**
   （比如"改了结构之后 train 内部还学得会吗"），不能用来排名。

## 六、局限

- holdout 只有 90 条，Acetaldehyde 只有 6 条；单条样本翻面就是 0.17 的 F1 波动
- 只测了一种切分（20%、固定种子），没做多次重切取平均
- 只测了 12 组配置，没覆盖"改结构"（分箱 / 加层），那些按官方规则本就不能声称续训
- 结论只对 A 包成立。B/C 是回归、按实体分块，内部切分的语义不同，需单独验证

## 七、复现

```powershell

python tools/probe_a_internal.py
# 选定后对 public val 报数（只跑一次）
python tools/probe_a_internal.py --final
```
