# 智训引擎 · rsi-harness

一个面向"数据分布会漂移"场景的持续训练系统。它不追求单次训练出最高分，而是试图回答一个更难的问题：

> 当工厂里的数据慢慢变得和训练时不一样了，模型该不该动？动多少？动错了怎么退回来？

本仓库是赛题 **"智训引擎"** 的参赛作品源码。三个任务的离线实验记录、十轮续训链、评测镜像构建脚本都在这里。

---

## 一句话结论

| 任务 | 指标 | 官方基线 | 我们提交 | 变化 |
|---|---|---|---|---|
| A · 六类气体识别 | Macro-F1 | 0.7140 | **0.7210** | +0.70pp |
| B · 轴承 RUL 回归 | RMSE（分钟） | 681.16 | **681.16** | 不变（主动选择） |
| C · 发动机 RUL 回归 | RMSE（循环） | 52.8686 | **50.9320** | −3.66% |

三个数字都在官方 `public/validation` 上复现过，与平台公布基线逐位一致。B 包不变不是没做，是六轮续训全部为负收益，我们判定"不动"才是正确决策——详见 [`docs/experiments.md`](docs/experiments.md)。

## 三分钟验证

```bash
# 1. 构建（离线，不联网，约 15 秒）
docker build -f Dockerfile -t rsi-harness:1.0 .

# 2. 跑一批数据（从文件喂，逐行 JSON）
docker run --rm --network none -i rsi-harness:1.0 < inputs.jsonl > outputs.jsonl

# 3. 看输出
head -c 300 outputs.jsonl
```

输入一行一个 JSON：

```json
{"task": "classification", "inputs": {"features": [0.1, -0.2, "...共128个数"]}}
```

输出一行一个 JSON：

```json
{"outputs": [{"label": "Ethanol", "score": 0.8731}, {"label": "Ethylene", "score": 0.0521}, "...共6个"]}
```

回归任务是 `{"outputs": {"value": 34.72}}`。

三个任务共用一个镜像，靠输入形状自动路由：有 `settings` 字段是 C，`features` 是字典是 B，是长度 128 的列表是 A。

## 这个系统在做什么

赛题的核心不是"训一个模型"，而是"提交一套没人管也能自己维持性能的系统"。我们的五环：

1. **监测**——每批数据进来，先算三个证据：特征分布偏移（PSI）、模型输出分布偏移、延迟到达的标签表现。三路必须同时看，单看一路会误判。
2. **归因**——判断这次偏移是"数据变了但规律没变"（调阈值就够），还是"规律本身变了"（必须重训）。这一步用两条 PSI 的**比值**判，不只看绝对值。
3. **决策**——四个动作：不动 / 校准阈值 / 重训 / 回滚。决策前过五道闸：预算不足强制不动、更新次数超限停手、冷却期内不许连动、评估门退步就拒、比基线差太多就回滚。
4. **执行**——真的去训、去改、去回滚。
5. **记账**——每次动作为什么发生、花了多少 CPU、结果变好还是变坏，全部落盘。这一环是评分表里"自主决策可追溯"的证据来源。

**最反直觉的一点**：在我们构造的漂移测试里，"什么都不做"的冻结基线排第 4，六种主动适应策略全在它下面（0.8065 vs 0.34–0.78）。所以系统最难的能力不是"改"，是**判断什么时候不该改**。

---

## 为什么推理期什么都不做

镜像里的 `predict.py` 是纯前向：读一行、算一次、写一行，不拟合、不校准、不重训、不维护统计量。

这不是没实现，是**主动设计**，依据三条：

1. `TRAINING_GUIDE.md:32` 明确禁止验证集/隐藏测试集参与拟合任何统计量——阈值校准、分布对齐、标准化重估**都算**"从测试数据里推出参数"，属于违规。
2. `tests/test_baselines.py:65-72` 对 `RUL` / `true_rul` / `Normalized_RUL` 字段直接 `assertRaises(ValueError)`，官方从设计上就禁止预测时读标签。
3. `baselines/predict.py:1` 注释写明 "no model execution hooks"——官方期望的就是一个无状态前向进程。

所以我们把"自进化"的全部证据放在**离线十轮链**里：每轮读上一轮历史、提假设、做实验、记录到 SwanLab、决定接受或拒绝，最后只把"挑出来的那一个权重"交给镜像。评分表要看的"自迭代证据"由这条链 + 记录提供，不由运行时动作提供。

## 目录

```
harness/            评测镜像的全部代码（纯 numpy，无第三方依赖除 numpy）
  predict.py          逐行读 stdin / 逐行写 stdout
  router.py           按输入 schema 路由到 A/B/C
  net.py              前向计算 + checkpoint 读取
  checkpoints/        官方原版权重（可复现基线）
  checkpoints_trained/十轮链挑出的权重（提交默认用这个）
src/                五环离线实现（监测、归因、决策、执行、记账）
tools/              十轮流水线、对照实验、SwanLab 上传、数据适配
docs/               设计文档与实验记录
experiments.md      两个合成流 × 10 组策略 × 3 seed 的完整结果
```

## 数据说明

本仓库**不含任何数据集**。官方数据包不随源码分发，镜像里也不打包样本——数据由平台通过管道喂入。

复现实验需要自行从赛事平台获取 `cpu-a-guide` / `cpu-b-rul` / `cpu-c-guide` 三个包，放到 `data/official/` 下。

## 已知限制

- 三个任务的十轮链只在 A 和 C 上带来正收益；B 包续训直接伤性能，我们选择保留官方权重。
- A 包的 Acetaldehyde 类在 batch2 上召回为 0，这是类间重叠上升导致的，任何分布监测都测不出，只有按类召回能测——而召回需要标签，评测时拿不到。这个局限我们写进了 [`docs/A包漂移诊断.md`](docs/A包漂移诊断.md)。
- 漂移监测的阈值（PSI 0.10 / 0.25）来自合成数据，在真实数据上尺子可能偏小，需要按数据重新标定。
